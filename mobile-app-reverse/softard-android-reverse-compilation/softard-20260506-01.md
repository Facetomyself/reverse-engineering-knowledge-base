##  第二步：找到并修改 root 检测逻辑

可以结合jadx看apk代码确认root检测的位置。可以看到在  ` MainActivity  ` 的  ` onCreate  `
处先调用了3个方法，如果任一返回true，视为有root，进入a方法。现在逻辑清晰了，开始看smali代码。


打开  ` MainActivity.smali  ` ，找到  ` onCreate  ` 方法：


    invoke-static {}, Lsg/vantagepoint/a/c;->a()Zmove-result v0if-nez v0, :cond_0        ← root检测1
    invoke-static {}, Lsg/vantagepoint/a/c;->b()Zmove-result v0if-nez v0, :cond_0        ← root检测2
    invoke-static {}, Lsg/vantagepoint/a/c;->c()Zmove-result v0if-eqz v0, :cond_1        ← root检测3，注意这里是 eqz，逻辑反的
    :cond_0const-string v0, "Root detected!"invoke-direct {p0, v0}, ...MainActivity;->a(...)V   ← 弹窗

所以修改方案很简单：把条件判断翻转，即代码检测到root了，但是我们改完条件他就不弹窗。

###  修改：反转跳转条件

最简单的绕过：把跳转条件全部反转，让 root 检测"永远通过"：

原来  |  改成  |  含义
---|---|---
` if-nez v0, :cond_0  ` |  ` if-eqz v0, :cond_0  ` |  非零跳 → 零才跳
` if-nez v0, :cond_0  ` |  ` if-eqz v0, :cond_0  ` |  同上
` if-eqz v0, :cond_1  ` |  ` if-nez v0, :cond_1  ` |  零跳 → 非零才跳

来来来，我们要学会在答案中找问题，问的多了学的才明白。 问：jadx看到的检测代码是有规律的3个连续判断，


    if (c.a() || c.b() || c.c()) {      a("Root detected!");  }

为什么，smali代码最后一个是eqz？想2分钟。


    if-nez v0, :cond_0if-nez v0, :cond_0if-eqz v0, :cond_1:cond_0走到弹窗:cond_1继续执行

试想一下，如果最后一个判断写成nez，那么代码应该是这样的：


    invoke-static {}, Lsg/vantagepoint/a/c;->c()Z  move-result v0
      if-nez v0, :cond_0
      goto :cond_1          # 如果都不满足，继续cond_1执行
      :cond_0  走到弹窗

所以差别就是多了一条goto跳转指令。原理就是，对于 || 运算，只要有一个为 true 就跳转执行 cond_0。前两个都有后续判断可以 fall-
through，所以用 if-nez "提前跳出"到 body。但 c.c() 是最后一个条件，没有更多判断了。编译器直接反转逻辑：

  * 若 c.c() 为 false（eqz）→ 跳到 :cond_1
  * 若 c.c() 为 true → fall-through 到 :cond_0 本质是同一语义的两种等价表达，编译器选择了 fall-through 进入 body 而不是跳转进入，减少了一次跳转指令。

这个就是编译器的指令优化。

继续看smali。除了改判断条件，我们还有另外的改法，就是让他弹窗代码失效，我们把退出app的代码删了，这样app就可以正常使用。

###  修改：屏蔽退出逻辑

` MainActivity$1  ` 是弹窗的 OK 按钮监听器，点击后直接  ` System.exit(0)  ` ：


    .method public onClick(Landroid/content/DialogInterface;I)V    .locals 0
        const/4 p1, 0x0    invoke-static {p1}, Ljava/lang/System;->exit(I)V
        return-void.end method


把  ` const/4  ` 和  ` invoke-static  ` 这两行删掉，只留  ` return-void  ` 。点 OK
就什么都不发生，App 可以继续使用。


当然了，这里还有其他修改的方法，逆向就是这样的，只要能达到目的，想改什么都行。注意，修改smali的时候尽量改判断条件，少删代码。因为直接删代码可能导致寄存器数量声明（
` .registers  ` ）和实际用量对不上，apktool 重打包时报错。像反转if逻辑只会改一个单词，不影响寄存器布局。

> "最小改动"是关键原则——只改你要改的那几个字，不动其他逻辑，出错概率最低。


##  第三步：回包 + 签名 + 安装

这里涉及到一个签名的内容，分享一个我日常用的重签名+自动安装签名后apk的脚本，自己可以照着代码修改成自己顺手的工具：


    #!/bin/bash# APK重签名全局命令# 用法: my_resign <输入APK> [输出APK]set -euo pipefail
    # ─── 颜色日志 ────────────────────────────────────────────────────RED='\033[0;31m'; GREEN='\033[0;32m'; YELLOW='\033[1;33m'; NC='\033[0m'log_info()  { echo -e "${GREEN}[INFO]${NC}  $*"; }log_warn()  { echo -e "${YELLOW}[WARN]${NC}  $*"; }log_error() { echo -e "${RED}[ERROR]${NC} $*" >&2; }
    # ─── 帮助 ────────────────────────────────────────────────────────if [ $# -eq 0 ] || [ "${1:-}" = "-h" ] || [ "${1:-}" = "--help" ]; then    echo "用法: my_resign <输入APK> [输出APK]"    echo ""    echo "  输入APK   必填，支持相对路径或绝对路径"    echo "  输出APK   可选，默认在输入APK同目录生成 <原文件名>_resigned.apk"    echo ""    echo "示例:"    echo "  my_resign app-release.apk"    echo "  my_resign app-release.apk output.apk"    exit 0fi
    # ─── 内置密钥库（绝对路径）──────────────────────────────────────KEYSTORE="/Users/admin/Documents/demo/anti/Safeguard/magicBox/resignKeystore"ALIAS="resign_alias"STORE_PASS="resign"KEY_PASS="resign"
    # ─── 参数处理（转为绝对路径）────────────────────────────────────INPUT_APK="$(cd "$(dirname "$1")" && pwd)/$(basename "$1")"if [ $# -ge 2 ]; then    OUTPUT_DIR="$(cd "$(dirname "$2")" 2>/dev/null && pwd)" || OUTPUT_DIR="$(pwd)"    OUTPUT_APK="$OUTPUT_DIR/$(basename "$2")"else    INPUT_DIR="$(dirname "$INPUT_APK")"    INPUT_BASE="$(basename "$INPUT_APK" .apk)"    OUTPUT_APK="$INPUT_DIR/${INPUT_BASE}_resigned.apk"fi
    # ─── 打印配置 ────────────────────────────────────────────────────log_info "INPUT_APK  = $INPUT_APK"log_info "OUTPUT_APK = $OUTPUT_APK"log_info "KEYSTORE   = $KEYSTORE"
    # ─── 工具检查 ────────────────────────────────────────────────────for tool in zip zipalign apksigner aapt; do    command -v "$tool" &>/dev/null || { log_error "缺少工具: $tool"; exit 1; }done
    # ─── 输入文件检查 ────────────────────────────────────────────────[ -f "$INPUT_APK" ]  || { log_error "输入APK不存在: $INPUT_APK"; exit 1; }[ -f "$KEYSTORE" ]   || { log_error "密钥库不存在: $KEYSTORE"; exit 1; }
    START_TIME=$(date +%s)
    # ─── 临时工作区 ──────────────────────────────────────────────────TEMP_DIR=$(mktemp -d)trap 'rm -rf "$TEMP_DIR"' EXIT
    # 步骤1: 复制原始APK（保留所有文件原始压缩格式）log_info "[1/4] 复制原始APK..."cp "$INPUT_APK" "$TEMP_DIR/work.apk"
    # 步骤2: 删除旧签名log_info "[2/4] 移除原始签名..."zip -q -d "$TEMP_DIR/work.apk" 'META-INF/*' 2>/dev/null || true
    # 步骤3: zipalign重新对齐log_info "[3/4] zipalign对齐..."zipalign -f -v -p 4 "$TEMP_DIR/work.apk" "$TEMP_DIR/aligned.apk" >/dev/null
    # 步骤4: 签名log_info "[4/4] apksigner签名 (V1+V2)..."apksigner sign \    --ks "$KEYSTORE" \    --ks-pass "pass:$STORE_PASS" \    --ks-key-alias "$ALIAS" \    --key-pass "pass:$KEY_PASS" \    --v1-signing-enabled true \    --v2-signing-enabled true \    --out "$TEMP_DIR/signed.apk" \    "$TEMP_DIR/aligned.apk"
    # 验证apksigner verify "$TEMP_DIR/signed.apk" || { log_error "签名验证失败"; exit 1; }
    # ─── 输出结果 ────────────────────────────────────────────────────mv "$TEMP_DIR/signed.apk" "$OUTPUT_APK"END_TIME=$(date +%s)log_info "重签名完成: $OUTPUT_APK ($(du -h "$OUTPUT_APK" | cut -f1), 耗时 $((END_TIME - START_TIME))s)"
    # ─── adb安装（设备在线才执行）───────────────────────────────────if adb get-state &>/dev/null; then    log_info "检测到ADB设备，开始安装..."    PACKAGE=$(aapt dump badging "$OUTPUT_APK" 2>/dev/null | grep "^package:" | grep -oE "name='[^']+'" | head -1 | sed "s/name='//;s/'//")    if [ -n "$PACKAGE" ]; then        log_info "包名: $PACKAGE"        adb uninstall "$PACKAGE" 2>/dev/null && log_info "已卸载旧包" || {            log_warn "常规卸载失败，尝试强制卸载..."            adb shell pm uninstall --user 0 "$PACKAGE" 2>/dev/null && log_info "强制卸载成功" || log_warn "卸载失败，需手动卸载后重试"        }    fi    adb install -r -t "$OUTPUT_APK" && log_info "安装成功: $PACKAGE"else    log_warn "未检测到ADB设备，跳过安装"fi


然后就可以继续进行重打包


    # 重打包apktool b uncrack_l1/ -o UnCrackable-Level1-patched.apk
    # 签名my_resign UnCrackable-Level1-patched.apk my_signed.apk
    # 签名脚本会自动卸载安装，也可以手动安装adb install my_signed.apk

这时候可以打开app验证是否可以绕过root检测了。这些命令都是基本工具，很多学逆向的都是看其他课程教学用到的比如mt管理器之类的工具，用工具很熟练，但导致的结果就是不知道什么原理。我的建议还是从基础命令入手，在电脑上多敲敲代码，然后做成自己顺手的工具后，工作效率是最高的。

这一节还是非常简单的，重点是体验smali的修改流程。实际上工程里面，不会有这么简单不混淆的java代码，而且重打包、重签名app都有非常多维度的检测手段。这个后面出了新手村难度就加大了。先练功吧。
