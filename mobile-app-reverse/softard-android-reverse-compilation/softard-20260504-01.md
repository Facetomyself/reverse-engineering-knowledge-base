##  为什么不直接看 jadx 反编译的 Java

很多人刚入门逆向，第一反应是：jadx 一拖，Java 代码出来了，何必学 Smali ？

原因有两个。

第一，jadx 给你看的是"翻译稿"，不是原文。它会做大量推断，比如把跳转指令还原成 if/else，把寄存器操作还原成变量。遇到混淆代码、加固
APP、或者某些编译器生成的奇怪字节码，jadx 要么报错，要么给你一段根本跑不起来的伪代码。

第二，你要改 APK 的话，改的还是 Smali，不是 Java。apktool 拆包出来的是  ` .smali  `
文件，你改完重打包，改的就是这一层。如果只会看 jadx 不会读 Smali，改的时候两眼一抹黑，完全不知道自己在动哪。

所以，Smali 不是可选项，是逆向的地基。


##  Smali 是什么

jadx 反编译出来的 Java 代码，是经过"翻译"过的，好看但不准确。APK 里真正存的是 DEX 字节码，而 Smali 就是 DEX
字节码的文本表示——就像 x86 汇编之于机器码，一一对应，可以互相转换。


    Java 源码 (.java)    ↓ javacJava 字节码 (.class)← JVM 用的    ↓ d8/dxDEX 字节码 (.dex)   ← ART/Dalvik 用的，二进制    ‖Smali              ← DEX 的文本表示，人类可读

apktool 拆包后，  ` smali/  ` 目录下每个  ` .smali  ` 文件对应原来的一个 Java 类。你要改 APK
的逻辑，改的就是这些文件。

好消息是 Smali 其实不难。指令集不大，格式固定，有几十条常用指令，掌握之后读起来比 ARM 汇编友好多了。


##  寄存器：v 和 p

Dalvik 是基于寄存器的虚拟机（JVM 是基于栈的）。这是个重要区别——JVM 靠压栈出栈传数据，Dalvik
靠寄存器传数据，更接近真实硬件的思路，执行效率也更高。

每个方法有自己固定数量的寄存器，分两种：


    v0, v1, v2 ...   ← 局部变量寄存器p0, p1, p2 ...   ← 参数寄存器

有一个细节是：  ** 实例方法的 p0 是 this  ** ，静态方法没有 this，所以 p0 直接是第一个参数。


    # public void foo(int a, int b)# p0 = this, p1 = a, p2 = b
    # public static void bar(int a, int b)# p0 = a, p1 = b

` .registers 4  ` 声明这个方法总共用几个寄存器，局部 + 参数加在一起算。

这个数字很关键。如果你往方法里加了新的局部变量，但没有增加  ` .registers  ` 的值，apktool 回包后运行时会报错，崩得很难看。新手改
Smali 第一次踩的坑十有八九是这个。

另外，  ` p  ` 和  ` v  ` 本质上是同一组寄存器，只是编号方式不同——p0 实际上对应的是编号  ` (registers数 - 参数数)
` 的那个寄存器。有些工具会把 Smali 里的 p 全展开成 v 显示，不要被搞混了。


##  类型描述符

方法签名里的类型缩写如下，如果经常写动态注册jni方法的会对这个比较熟悉：


    I → intZ → booleanB → byteS → shortJ → longF → floatD → doubleC → charV → void[B → byte[]Ljava/lang/String;

看到  ` (Ljava/lang/String;I)Z  ` ，翻译过来就是：  ` boolean fun(String a, int b)  ` 。


有个小规律：  ** 基本类型全是单字母大写，只有引用类型是  ` L...;  ` 格式  ** 。Java 里最容易混淆的是  ` boolean  `
→  ` Z  ` （不是  ` B  ` ，B 是 byte），这个背一次就记住了，反正踩过一次坑之后不会忘。

` long  ` 和  ` double  ` 比较特殊——它们在寄存器里占两个槽位。声明  ` .registers  `
的时候要算进去，否则又是报错。


##  常用指令

** 方法调用：  **


    invoke-virtual {p0, p1}, Ljava/lang/String;->equals(Ljava/lang/Object;)Z# → 实例方法，可能有子类覆写，走虚分派
    invoke-static {p1}, Ljava/lang/Integer;->parseInt(Ljava/lang/String;)I# → 静态方法
    invoke-direct {p0}, Lcom/example/Foo;-><init>()V# → 构造方法或 private 方法（编译期确定，不需要虚分派）
    invoke-interface {p0, p1}, Ljava/util/List;->get(I)Ljava/lang/Object;# → 接口方法调用

选哪个 invoke 不用死记，看一下就能判断：静态方法 → static，构造或 private → direct，接口 →
interface，其余实例方法 → virtual。

调用完取返回值必须紧跟  ` move-result  ` ：


    invoke-virtual {p1, v0}, Ljava/lang/String;->equals(Ljava/lang/Object;)Zmove-result v0        ← 基本类型用这个# move-result-object v0  ← 引用类型用这个

这里有个坑：  ** 如果你不需要返回值，可以不写 move-result，但只要你写了，就必须紧跟在 invoke 后面，中间不能有其他指令  **
，否则回包报错。

** 字段读写：  **


    iget v0, p0, Lcom/example/Foo;->count:I      ← 实例字段读iput v0, p0, Lcom/example/Foo;->count:I      ← 实例字段写sget v0, Lcom/example/Foo;->TAG:Ljava/lang/String;  ← 静态字段读sput v0, Lcom/example/Foo;->TAG:Ljava/lang/String;  ← 静态字段写

` i  ` 开头是实例字段，  ` s  ` 开头是静态字段，get/put 对应读/写，拼起来就行了。

** 常量赋值：  **


    const/4 v0, 0x0        ← 4-bit 小整数，-8 到 7const/16 v0, 0x100     ← 16-bit 整数const v0, 0x12345678   ← 32-bit 整数const-string v0, "hello"  ← 字符串const-class v0, Ljava/lang/String;  ← Class 对象

改 Smali 最高频的操作之一就是往方法里插一个  ` const/4 v0, 0x0  ` ，让某个检测结果永远返回 false。

** 跳转：  **


    if-eqz v0, :label_true      ← v0 == 0 则跳if-nez v0, :label_true      ← v0 != 0 则跳if-eq v0, v1, :label_true   ← v0 == v1 则跳if-gt v0, v1, :label_true   ← v0 > v1 则跳goto :label_target          ← 无条件跳

逆向里最常改的就是这里——把  ` if-eqz  ` 改成  ` if-nez  ` ，条件反转，绕过检测。


##  读一段完整的 Smali

这里可以来一段完整的例子试一下。


    .method public checkPassword(Ljava/lang/String;)Z    .registers 3
        const-string v0, "secret123"    invoke-virtual {p1, v0}, Ljava/lang/String;->equals(Ljava/lang/Object;)Z    move-result v0    return v0.end method


对应 Java：


    public boolean checkPassword(String a) {    return a.equals("secret123");}

逐行拆解一下：

  * ` .registers 3  ` ：总共 3 个寄存器。参数是  ` this(p0)  ` 和  ` String a(p1)  ` ，占 2 个，v0 是唯一的局部寄存器。
  * ` const-string v0, "secret123"  ` ：把字符串常量装进 v0。
  * ` invoke-virtual {p1, v0}, ...->equals(...)  ` ：调用  ` p1.equals(v0)  ` ，也就是  ` a.equals("secret123")  ` 。注意花括号里第一个是调用对象，后面是参数。
  * ` move-result v0  ` ：把 equals 的返回值（boolean）装进 v0，这时候 v0 里的字符串引用被覆盖掉了——寄存器复用，正常操作。
  * ` return v0  ` ：返回。

这段代码在逆向里极其典型——  ** 明文密码直接躺在  ` const-string  ` 里  ** 。真实 APP
会把字符串加密，运行时解密，这里装的是密文；但思路是一样的，找到这里就找到了入口。

再看一个带跳转的例子：


    .method public isVip(I)Z    .registers 3
        const/16 v0, 0x64          # v0 = 100    if-lt p1, v0, :not_vip     # if (p1 < 100) goto not_vip
        const/4 v0, 0x1    return v0                  # return true
        :not_vip    const/4 v0, 0x0    return v0                  # return false.end method

对应 Java：


    public boolean isVip(int level) {    return level >= 100;}

这里要绕过 VIP 检测，最简单的改法就是在方法开头加两行，直接  ` const/4 v0, 0x1; return v0  `
，后面的逻辑全跳过。或者把  ` if-lt  ` 改成  ` if-ge  `
，条件反转。两种方式都能达到目的，改哪里取决于你想让逻辑看起来更自然，还是改动越少越好。


##  小结

Smali 不难，就是 DEX 的汇编。掌握三件事就够用：

  1. ** 寄存器命名  ** ：v 是局部，p 是参数，p0 是 this（实例方法）；改方法时注意  ` .registers  ` 的值要同步更新
  2. ** 类型描述符  ** ：  ` I/Z/B/[X/Lxxx;  ` 把映射关系背下来
  3. ** 四种 invoke  ** ：virtual / static / direct / interface，看调用类型选对应的
