## 一、类加载器子系统（ClassLoader）

**概述：** 将二进制流读入内存，生产一个 Class 对象。

### 1. 加载（Loading）

#### 类加载器

**启动类加载器（Bootstrap ClassLoader）**

- C++ 实现
- 主要负责加载 `<JAVA_HOME>/lib` 目录，或被 `-Xbootclasspath` 指定路径中、且文件名被虚拟机识别的文件
- 是所有类加载器的父类

**扩展类加载器（Extension ClassLoader）**

- Java 实现
- 独立于虚拟机
- 主要负责加载 `<JAVA_HOME>/lib/ext` 目录下的 jar 包，以及 `java.ext.dirs` 系统变量所指定路径的类库

**应用类加载器 / 系统类加载器（Application ClassLoader）**

- Java 实现
- 独立于虚拟机
- 主要负责加载用户类路径（Classpath）上的类库
- 如果没有实现自定义类加载器，这个加载器就是程序中默认的加载器

**双亲委派优先级（原图写「优先加载」）：**

`Application ClassLoader → Extension ClassLoader → Bootstrap ClassLoader`

（实际查找顺序是先委托父加载器，父加载器找不到再由自己加载。）

#### 常用类加载器应用场景

- **Web 容器（如 Tomcat）：** 每个 Web 应用都有自己的类加载器，保证应用相互隔离，防止类冲突
- **OSGi：** 使用类加载器动态加载和卸载模块，实现灵活的模块化架构
- **热加载：** 开发环境中的热部署（如 JRebel），通过自定义类加载器支持类的动态重载

### 2. 链接（Linking）

**验证（Verification）**

验证加载进来的二进制是否符合一定格式、是否规范、是否符合当前 JVM 版本等。

**准备（Preparation）**

为静态变量（类变量）赋初始值，即为它们在方法区划分内存空间。
这里是「静态变量」，并且是类型默认初始值（零值）。

**解析（Resolution）**

（原图误标为 Preparation）

将常量池的符号引用转化为直接引用：

- **符号引用：** 可以理解为只是一个替代标签，是一个字面量，没有实质性意义，只是一个代表
- **直接引用：** 是一个真实引用，在内存中可以通过这个引用查找到目标

### 3. 初始化（Initialization）

执行一些静态代码块，为静态变量赋初值。
这里的赋值才是代码里写的值；准备阶段只是设置初始值（占个坑）。

## 二、运行时数据区（Runtime Data Area）

### 1. 方法区（Method Area）

**存储内容：** 类信息、常量、静态变量，以及即时编译器（JIT）编译后的代码。

**共享性：** 属于线程共享区域，所有线程共享方法区内存。

**实现变化：**

- JDK 7 及之前：HotSpot 使用永久代（PermGen）实现方法区，主要存储类信息、静态变量等
- JDK 8 以后：永久代被移除，改为使用元空间（Metaspace）
  - 元空间使用本地内存（Native Memory），以提高性能并避免 OOM（内存溢出）
  - 元空间可以动态调整大小，而永久代大小是固定的
- JDK 8 之前用永久代（PermGen），JDK 8 之后被元空间（Metaspace）取代，元空间用的是本地内存

### 2. 堆（Heap）

**概述：** 用于存放所有线程共享的对象和数组，是垃圾回收的主要区域。

**分代结构：**

- **Eden（新生代）**
  新对象最初会被分配到 Eden 区。Eden 区较大，频繁进行垃圾回收。

- **Survivor（幸存区）**
  两个 Survivor 区 S0 和 S1 交替使用。
  新对象在经历一次垃圾回收后会存放到其中一个 Survivor 区；进一步存活的对象会移动到另一个 Survivor 区，最终晋升到老年代。

- **老年代**
  长生命周期对象经过多次垃圾回收后会被迁移到老年代。
  Major GC 在老年代进行，频率较低、耗时较长。

### 3. 虚拟机栈（JVM Stack）

- 每个线程创建一栈，用来保存局部变量
- 局部变量中存放的是基本类型（int、float 等）以及对象引用
- 栈是线程私有的，生命周期与线程相同

**栈帧（Stack Frame）：**

每当一个方法被调用时，虚拟机会在栈中创建一个新的栈帧。
栈帧用于存储方法的局部变量表、操作数栈、常量池引用等。
方法执行完毕后，栈帧会被弹出，释放内存。

### 4. 本地方法栈（Native Method Stack）

- 为本地方法服务，使用 JNI（Java Native Interface）调用的本地代码在此区域分配内存
- 和虚拟机栈类似，也是线程私有的

### 5. 程序计数器（Program Counter Register）

- 是一个小的内存区域，保存当前线程执行的字节码指令的地址或行号
- 每个线程都有一个独立的计数器，属于线程私有

**特点：**

唯一不会出现 OOM 的内存区域。
它记录当前字节码行号，非常小。
多线程环境下，每个线程都有自己的程序计数器，以实现线程切换时的准确恢复。

## 三、执行引擎（Execution Engine）

**概述：** 执行引擎负责将字节码转化为机器指令并执行。

- **解释器（Interpreter）：** 逐行解释字节码并执行，适用于程序首次运行时
- **即时编译器（JIT Compiler）：** 将热点代码（频繁执行的代码）编译为机器码执行，提升效率
- **JIT 还可能发生指令重排序：** 一般用 `volatile` 来解决该问题

**编译器类型：**

- **C1（Client Compiler）：** 用于快速启动的轻量级优化，适用于客户端应用程序
- **C2（Server Compiler）：** 用于长时间运行的重度优化，适用于服务器端应用程序

## 四、本地方法接口（JNI，Java Native Interface）

本地方法接口允许 Java 调用非 Java 代码（如 C/C++），便于与操作系统或其他本地库进行交互。
JNI 提供跨语言调用能力，使 Java 程序可以访问操作系统级别的功能或高性能库。

## 阅读提示

1. **类加载完整顺序：** 加载 → 验证 → 准备 → 解析 → 初始化（链接包含验证、准备、解析）。
2. **线程共享 vs 私有：**
   - 共享：堆、方法区
   - 私有：虚拟机栈、本地方法栈、程序计数器
3. **JDK 8 关键变化：** PermGen → Metaspace（本地内存）。
