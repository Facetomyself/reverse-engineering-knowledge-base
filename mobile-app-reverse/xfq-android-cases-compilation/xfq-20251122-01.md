# 安居客 17.28.1 nsign：MD5 一位改写与四段拼接

> 来源: 知识星球：逆向学习交流
> 原始发布时间: 2025-11-22
> 归档日期: 2026-09-06
> 分类: mobile-app-reverse
>
> 安居客 `com.anjuke.android.app` 17.28.1 的 `nsign` 在 `libsignutil.so` 静态注册的 `SignUtil.getSign0`。输出 56 字符：固定 `1000` + 改写后的 32 位 MD5 + 12 位长度/计数 nibble + `str3` UUID 前 8 位。MD5 是标准压缩函数，只改写 `digest[0]` 指向的那一字节。本篇补 Java/Native hook 点与参数形状；RVA 按当前 SO 重核。不收录设备字段、抓包原文和可直接跑的过检测脚本。

## 收录说明

原附件含 `libmsaoaidsec.so` 线程替换脚本和一次搜索接口的完整 map。本篇只归档 `nsign` 闭合模型、观察窗口和 key 名列表。MSA 检测面另见 [豆瓣 HMAC-SHA1 与 MSA 定位](../reversenotes-android-compilation/douban-hmac-sig.md)。

## 案例边界

| 项 | 内容 |
|---|---|
| 包名 | `com.anjuke.android.app` |
| 观察版本 | 17.28.1 |
| Java | `com.anjuke.mobile.sign.SignUtil.getSign0` |
| Native | `libsignutil.so`（静态注册，观察样本为 32 位 Thumb） |
| 出参 | 56 字符 `nsign` |

`getSign0(path, bodyHash, map, uuid, flag)`：`path` 是接口路径，`bodyHash` 在空 POST 体上是标准空串 MD5 `d41d8cd98f00b204e9800998ecf8427e`，`map` 是 `Map<String, byte[]>`，`uuid` 是本次随机 `str3`，`flag` 观察为 `0`。

## Hook 窗口（只记点，不贴脚本）

| 层 | 点 | 参数形状 | 观察备注 |
|---|---|---|---|
| Java | `SignUtil.getSign0` | `(String, String, Map<String,byte[]>, String, int) -> String` | 出参 56 字符；map 值是 byte[]，不要用 `toString()` 当明文 |
| Native | `libsignutil.so` `SIGNMD5` | `arg0` C 串明文，`arg1` 长度，`arg2` 写出 32 hex | 观察 RVA `0x10FC`，Thumb 入口 `+1` |
| Native | 一位改写 | 读第一字节 ASCII，写回 `utf[4 + (first & 0xF)]` | 观察指令点 `0x1B30`，同样 Thumb `+1` |

上述 RVA 只对作者当时的 `libsignutil.so` 有效。换版本先按导出名 / 交叉引用重核，不要把 `base+0x10FC` 抄到新包。

## 四段结构

```text
nsign = "1000" + mutated_md5(32) + nibbles(12) + uuid[:8]
```

### 1. 前缀 `1000`

SO 里写死的 ASCII `0x31 0x30 0x30 0x30`。

### 2. 标准 MD5 后改一位

明文拼接：

```text
fixed32 || path || bodyHash || concat(map_kv)
```

`fixed32` 是样本内嵌的 32 hex 常量，必须从当前 SO 回读，文内不写具体值。`concat(map_kv)` 的 key 顺序作者按一次搜索列表的抓包映射表复现，**不是**已证明的 `TreeMap` / `LinkedHashMap` 排序；换接口要重新对照。

观察过的搜索列表 key 名（无值）：

```text
58clientid, _guid, o, openudid, pm, page, page_size, qtime,
sdplocdata, gmid, keywords, m, manufacturer, map_type, app,
ajk_city_id, cid, city_id, cv, entry, from, udid3, uuid, v, version_code
```

这些名字只说明字段集合。`udid` / `openudid` / `uuid` 的取值是设备锚点，不进知识库。

`SIGNMD5` 对上述明文做标准 MD5，得到 32 hex，再按字节改写：

```text
d = list(md5_hex)
d[ord(d[0]) & 0xF] = d[0]
mutated = ''.join(d)
```

对应汇编是把 `utf[4]`（MD5 第一字节的 ASCII）写回 `utf[4 + (first & 0xF)]`。

### 3. 12 位 nibble

`utf[36:48]` 用表 `'0123456789abcdef'` 编码三个 16 位量：Java `flag`、`map` 全部 key/value 的字节长度和、`map.size()`。只是长度指纹，不含业务明文。

### 4. UUID 前 8 位

`utf[48:56] = str3[:8]`，即 `UUID.randomUUID()` 去掉连字符前的前 8 hex。

## MSA 观察窗口（不是绕过步骤）

17.28.1 上通用抓包插件即可过证书校验；Frida 则可能在 `libmsaoaidsec.so` 加载期闪退。可复用的判断与豆瓣同族：

- hook `dlopen` / `android_dlopen_ext` 时，该 SO 常有 enter 无 leave
- 后续观察应落到 `linker` 的 `soinfo::call_constructors`（符号含 `__dl__ZN6soinfo17call_constructorsEv`）
- 该窗口内再看 `pthread_create` 的 `start_routine` 是否落在 `libmsaoaidsec.so`

作者当时看到的三个 `start_routine` RVA 是 `0x11e1d` / `0x127f1` / `0x19c09`。换 SO 必须重核。本篇不收录把这些地址 `Interceptor.replace` 成空函数的脚本。

## 边界

- `serverAccepted` 仍要业务 readback；本地拼出 56 字符只证明形状。
- 不收录附件 zip、Frida 替换脚本和抓包里的 `udid` / `openudid`。
- 58 同系其它 App 若共用 `libsignutil.so`，先核版本与 `fixed32`，不要直接套 17.28.1。
