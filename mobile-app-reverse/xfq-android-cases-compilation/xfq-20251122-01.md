# 安居客 17.28.1 nsign：MD5 一位改写与四段拼接

> 来源: 知识星球：逆向学习交流
> 原始发布时间: 2025-11-22
> 归档日期: 2026-09-06
> 分类: mobile-app-reverse
>
> 安居客 `com.anjuke.android.app` 17.28.1 的 `nsign` 在 `libsignutil.so` 静态注册的 `SignUtil.getSign0`。输出 56 字符：固定 `1000` + 改写后的 32 位 MD5 + 12 位长度/计数 nibble + `str3` UUID 前 8 位。MD5 是标准压缩函数，只改写 `digest[0]` 指向的那一字节。附件 hook 脚本、未脱敏 deviceId 与 zip 未收录。

## 收录说明

原附件含 `libmsaoaidsec.so` 线程替换脚本。本篇只归档 `nsign` 闭合模型，不收录检测绕过步骤。MSA 检测面见 [豆瓣 HMAC-SHA1 与 MSA 定位](../reversenotes-android-compilation/douban-hmac-sig.md)。

## 案例边界

| 项 | 内容 |
|---|---|
| 包名 | `com.anjuke.android.app` |
| 观察版本 | 17.28.1 |
| Java | `com.anjuke.mobile.sign.SignUtil.getSign0` |
| Native | `libsignutil.so`（静态注册） |
| 出参 | 56 字符 `nsign` |

`getSign0(path, bodyHash, map, uuid, flag)`：`path` 是接口路径，`bodyHash` 搜索接口上是空体 MD5，`map` 是请求参数，`uuid` 是本次随机 `str3`，`flag` 观察为 `0`。

## 四段结构

```text
nsign = "1000" + mutated_md5(32) + nibbles(12) + uuid[:8]
```

### 1. 前缀 `1000`

SO 里写死的 ASCII `0x31 0x30 0x30 0x30`。

### 2. 标准 MD5 后改一位

明文拼接：

```text
fixed32 || path || bodyHash || concat(map_kv)
```

`fixed32` 是样本内嵌的 32 hex 常量。`concat(map_kv)` 的 key 顺序作者按一次抓包映射表复现，**不是**已证明的 `TreeMap`/`LinkedHashMap` 排序；换接口要重新对照。

`SIGNMD5` 对上述明文做标准 MD5，得到 32 hex，再按字节改写：

```text
d = list(md5_hex)
d[ord(d[0]) & 0xF] = d[0]
mutated = ''.join(d)
```

对应汇编是把 `utf[4]`（MD5 第一字节的 ASCII）写回 `utf[4 + (first & 0xF)]`。

### 3. 12 位 nibble

`utf[36:48]` 用表 `'0123456789abcdef'` 编码三个 16 位量：Java `flag`、`map` 全部 key/value 的字节长度和、`map.size()`。只是长度指纹，不含业务明文。

### 4. UUID 前 8 位

`utf[48:56] = str3[:8]`，即 `UUID.randomUUID()` 去掉连字符前的前 8 hex。

## 边界

- `serverAccepted` 仍要业务 readback；本地拼出 56 字符只证明形状。
- 不收录附件 zip、Frida 替换脚本和抓包里的 `udid` / `openudid`。
- 58 同系其它 App 若共用 `libsignutil.so`，先核版本与 `fixed32`，不要直接套 17.28.1。
