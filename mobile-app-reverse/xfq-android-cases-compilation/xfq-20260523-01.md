# AppsFlyer androidevent：PBKDF2 + AES-CBC 纯算

> 广告 SDK AppsFlyer 的 `androidevent` 请求体不是整包 AES。固定盐与 app 侧 `devKey` 做 PBKDF2-SHA1（10000 次、16 字节）得到 AES-128 key；密文布局是 `ciphertext || IV(16) || unused(8)`，解密后再去 PKCS#7。附件脚本和未脱敏抓包未收录。

## 收录说明

原话题只给了算法骨架和一份 `af_decode.txt`。本文只保留可复用的派生与拆包规则。`devKey` 是每个接入 App 自己的 AppsFlyer key，必须从目标包提取；文内不写具体业务 key。盐在样本里曾被写成 8 字节全零占位，归档时按「需从目标 SO 回读」处理，不得把占位盐当成已闭合。

## 算法

| 项 | 内容 |
|---|---|
| 目标 | `androidevent` 请求体二进制 |
| KDF | `PBKDF2(password=devKey, salt, dkLen=16, count=10000, hmac=SHA1)` |
| 对称 | AES-128-CBC，PKCS#7 |
| 体布局 | `ciphertext = body[:-24]`；`iv = body[-24:-8]`；末 8 字节不参与解密 |

```text
devKey  --PBKDF2-SHA1(10000, dkLen=16, salt)-->  AES key
body[:-24]  +  body[-24:-8]  --AES-CBC-->  PKCS#7 strip  -->  plaintext
```

## 边界

- 盐必须从当前样本的 Native 常量回读；全零只是作者草稿占位。
- 同一套拆包对「换 App / 换 `devKey`」仍然成立，换盐或改迭代次数则要重新取证。
- 不收录上报样本、业务事件明文和附件 zip。
