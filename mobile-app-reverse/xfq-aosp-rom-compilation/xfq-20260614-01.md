## 正文

验证机型：Pixel 7 / panther / serial `35051FDH2000NQ`

## 需求

在现有 AOSP ROM 基础上做开发使用优化：

1. 默认打开开发者模式。
2. 默认开启 Stay awake，接电/USB 时不息屏。
3. 关闭自动熄屏。
4. 默认关闭系统自动更新开关。
5. 默认开启 USB 调试，并允许当前 ROM 作为开发机环境直接 adb 连接。
6. 默认亮度调低到接近手工调节后的观感。

## 主要代码改动

### 1. Panther 产品配置

文件：`device/google/pantah/aosp_panther.mk`

- 把 `ROMManager` 与权限 XML 放入 `PRODUCT_PACKAGES`。
- 增加开发者便利默认属性：
  - `persist.sys.usb.config=adb`
  - `ro.adb.secure=0`
  - `ro.xf.default_screen_brightness=8`

`ro.xf.default_screen_brightness` 是本 ROM 自己使用的只读属性，用来告诉 framework：第一次启动时如果 SettingsProvider 写入的 int 亮度就是 ROM 默认值，就优先保留这个 int 值，避免被 Pixel 设备侧 float 默认亮度覆盖。

另外，当前导出的 `device_google_pantah.patch` 中还包含 `panther/overlay/.../config.xml` 的 `config_screenBrightnessSettingDefaultFloat=0.027559055` 尝试值；实机验证显示运行时 lookup 仍为 Pixel 显示配置的 `0.17429718`，所以最终生效点不是这个 overlay，而是 SettingsProvider int 默认值加 BrightnessSynchronizer 保护。该 overlay 改动保留为本次已验证镜像的源码状态记录，后续可单独清理。

### 2. SettingsProvider 默认值

文件：`frameworks/base/packages/SettingsProvider/res/values/defaults.xml`

关键默认值：

- `def_screen_off_timeout=2147483647`：近似永不自动息屏。
- `def_screen_brightness=8`：低亮度默认值。
- `def_stay_on_while_plugged_in=true`：接电保持唤醒。
- `def_development_settings_enabled=true`：默认开发者模式开启。
- `def_adb_enabled=true`：默认 adb 开启。
- `def_ota_disable_automatic_update=true`：默认关闭 OTA 自动更新。

文件：`frameworks/base/packages/SettingsProvider/src/com/android/providers/settings/DatabaseHelper.java`

- 在初始化 global settings 时写入 `Settings.Global.ADB_ENABLED` 默认值。
- 在初始化 global settings 时写入 `Settings.Global.OTA_DISABLE_AUTOMATIC_UPDATE` 默认值。

### 3. 亮度同步保护

文件：`frameworks/base/core/java/com/android/internal/display/BrightnessSynchronizer.java`

背景：Android 13 同时存在旧的 int 亮度设置和新的 float 亮度设置，系统启动时 `BrightnessSynchronizer` 会在两者之间同步。Pixel 7 运行时的 float 默认亮度仍来自设备显示配置，值为 `0.17429718`，如果不处理，会把我们在 SettingsProvider 中写入的低 int 亮度覆盖成约 `45`。

本次增加逻辑：

- 如果系统属性 `ro.xf.default_screen_brightness` 存在；
- 当前 int 亮度等于 ROM 默认值；
- 当前 float 默认值和 int 转换出来的 float 不一致；

则启动同步时优先把 int 默认值同步到 float/显示侧，而不是让 Pixel float 默认值覆盖 int 默认值。

这样只影响本 ROM 声明过的第一次默认值场景，不改变用户手动调节后的正常同步逻辑。

## AOSP 亮度知识补充

AOSP/Pixel 亮度里容易混淆三个“数值空间”：

1. **SettingsProvider 旧 int 值**
   - 键：`settings get system screen_brightness`
   - 范围传统上是 `0..255`。
   - 我们现在默认写入 `8`。

2. **DisplayManager / PowerManager float 值**
   - 键：`screen_brightness_float`，或 `dumpsys power/display` 中的默认亮度。
   - 范围通常是 `0.0..1.0`。
   - Pixel 7 运行时显示默认值为 `0.17429718`。

3. **快捷设置亮度条 gamma 空间**
   - SystemUI 亮度条不是线性显示 int/float。
   - `BrightnessController` 使用 `BrightnessUtils.convertLinearToGammaFloat(...)` 把线性亮度转换到 gamma slider 空间。
   - slider 最大值是 `GAMMA_SPACE_MAX=65535`。
   - 所以下拉亮度条显示的“百分比/位置”不是 `screen_brightness / 255`。

这也是为什么之前看到：

```text
screen_brightness=45
config_screenBrightnessSettingDefaultFloat=0.17429718
```

但下拉亮度条看起来像 80%+。按 SystemUI 的 gamma/H​​LG 映射，`0.17429718` 在线性亮度里不算 80%，但会映射到较高的 slider 位置。
