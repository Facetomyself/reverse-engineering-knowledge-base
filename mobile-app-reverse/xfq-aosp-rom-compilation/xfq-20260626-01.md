## 正文

## 0. 结论先写清楚

WebView Debug 这条线分成两部分：

1. **ROM/Chromium 负责真的能强开 DevTools**：目标 App 即使调用 `WebView.setWebContentsDebuggingEnabled(false)`，ROM 仍然可以按包开启 WebView DevTools。
2. **检测/隐藏单独做**：App 能看到哪些痕迹、后续 KPM 怎么隐藏，统一放到 `notes/20260629-webview-detection-plan.md`，不再和 Chromium 强开文档混在一起。

当前已落地：

- 自编译 Chromium WebView，替换 AOSP `external/chromium-webview/prebuilt/arm64/webview.apk`。
- Chromium patch 只保留“按 ROMManager 配置强开 DevTools”，不做 socket 改名、不做隐藏。
- ROMManager 全局/按 App 开关可写入 WebView Debug 配置。
- `WebViewDebugProbe` 作为第三方语义 demo 放入 preload data-seed，用于验证 DevTools 可连接。
- DevTools frontend 404 已修复为本机 Chrome bundled frontend。

旧文档合并来源：

- `notes/20260613-webview-debug-analysis.md`
- `notes/20260626-webview-chromium-debug-stealth-plan.md`
- `notes/20260628-webview-debug-detection-demo.md` 中非检测部分

## 1. 需求介绍

最初观察到 `aosp_panther-userdebug` 下系统预编译 WebView 已经能被 `chrome://inspect` 发现，当时误以为 ROMManager 的 WebView debug 开关意义不大。后面需求变了：

- 不能依赖 `userdebug` / `eng` 默认行为；最终 ROM 以 `user` 版本为准。
- 不能只在 framework 层调用 `WebView.setWebContentsDebuggingEnabled(true)`。
- 需要 ROMManager 能对指定 App 强开 WebView DevTools。
- App 主动调用 `setWebContentsDebuggingEnabled(false)` 时，不应直接关闭 ROM 授权的调试能力。
- 完整 Chromium 源码和构建缓存不能进入补丁仓库，仓库只记录脚本、patch、接入方式和验证证据。

## 3. 方案取舍

| 方案 | 优点 | 缺点 | 结论 |
|---|---|---|---|
| 继续依赖 userdebug 默认可调试 | 不用改 WebView | user 版本不可控，且 userdebug 特征明显 | 不采用 |
| framework 层强行调用 Java API | 改动小 | App 自己可调用关闭，语义不稳定 | 不作为主方案 |
| 替换 Chromium WebView prebuilt | 能在 provider 内核侧控制 DevTools | Chromium 构建重、耗时长 | 采用 |
| 新增自定义 WebView provider 包名 | 和原 provider 隔离 | provider 元数据更容易被检测 | 默认不采用 |
| 改 socket 名/隐藏痕迹 | 短期看起来更隐蔽 | 容易漏 `/proc`/connect/CDP 检测，Chromium 维护复杂 | 从本功能剥离 |
| Chromium 只强开，隐藏交给检测矩阵/KPM | 职责清晰，可验证 | 需要单独做检测/隐藏分支 | 采用 |

### 4.5 DevTools frontend 404 修复

现象：Chrome/inspect 打开 target 跳到：

```text
https://chrome-devtools-frontend.appspot.com/serve_rev/@/inspector.html...
```

并显示 HTTP 404。

根因：Chromium checkout 的 `build/util/LASTCHANGE` 为 `LASTCHANGE=0`，Android WebView 又没有内置 DevTools frontend resources，导致 `/json/list` 暴露 `serve_rev/@/inspector.html`。

修复：Android 下将 `DevToolsHttpHandler::GetFrontendURLInternal()` fallback 改成本机 Chrome bundled frontend：

```text
devtools://devtools/bundled/inspector.html?ws=<host>/devtools/page/<id>
```

验证后 `/json/list` 返回：

```text
"devtoolsFrontendUrl": "devtools://devtools/bundled/inspector.html?ws=127.0.0.1:9222/devtools/page/..."
```

## 6. 优缺点与边界

优点：

- 不依赖 userdebug，方向上适配 user ROM。
- Debug 能力在 WebView provider 内核侧实现，Java API 表面不再是唯一开关。
- ROMManager 可以按包控制，方便和其它 App 级功能保持一致。
- 隐藏能力不混入 Chromium，避免后续维护和特征风险扩大。

缺点：

- Chromium 同步/编译重，必须控制 `JOBS`，不能和 AOSP 抢满机器。
- 自编译 WebView 的 provider 元数据、APK/hash、native 字符串仍可能被目标 App 对比。
- 当前 userdebug 设备会默认开启 WebView DevTools，验证“非 debug build 下 ROM 强开差异”必须用 user 构建。

边界：

- 本文只负责“确实可强开”和 ROMManager 控制链路。
- `/proc/net/unix`、`/proc/self/fd`、主动 `connect()`、`/json/list` 等检测/隐藏不在本文实现，见 `notes/20260629-webview-detection-plan.md`。
- WebView 深度 hook 只是路线，不在当前强开功能里一口气实现。

## 7. 后续路线

### 7.1 WebView 深度 Hook 候选 API

Java WebView API：

| 类别 | API | 价值 |
|---|---|---|
| 生命周期 | `WebView.<init>` / `destroy` / attach/detach | 捕获实例和页面生命周期 |
| 加载 | `loadUrl` / `postUrl` / `loadData*` | URL、headers、post body、HTML 片段 |
| JS | `evaluateJavascript` / `loadUrl("javascript:")` | Native -> JS 调用链 |
| Bridge | `addJavascriptInterface` / `removeJavascriptInterface` | JSBridge 名称、对象类、暴露面 |
| Settings | `WebSettings` setter/getter | JS/file/mixed-content/UA/storage 安全面 |
| Cookie | `CookieManager.setCookie/getCookie` | 登录态、风控参数 |

WebViewClient / WebChromeClient：

| API | 价值 |
|---|---|
| `shouldOverrideUrlLoading` | scheme 跳转、路由、支付/登录桥 |
| `shouldInterceptRequest` | Java 可见资源请求与 headers |
| `onPageStarted/onPageFinished` | 页面生命周期 |
| `onReceivedSslError/onReceivedError` | TLS/网络错误 |
| `onConsoleMessage` | 前端 console 与错误 |
| `onPermissionRequest` | camera/mic/location 权限 |

JS polyfill 方向：

```text
XMLHttpRequest.open/send/setRequestHeader
fetch
navigator.sendBeacon
WebSocket constructor/send
console.log/info/warn/error/debug
document.createElement('script')
ReactNativeWebView.postMessage
```

Chromium 内核深点：

| 层 | 候选点 | 价值 |
|---|---|---|
| DevTools | AwDevToolsServer / DevToolsAgentHost | target 控制 |
| net | URLRequest / NetworkService | headers/body/redirect/cookie |
| Blink | frame/document/script execution | JS 注入、DOM、iframe |
| V8 | script compile/run | JS 代码与调用栈 |
| WebSocket | handshake/frame | WS 明文数据 |
| Storage | cookie/localStorage/indexedDB/cache | H5 状态 |

### 7.2 后续原则

- 强开能力、检测矩阵、隐藏策略、深度 hook 必须拆 feature 做。
- 不把 Behavior、SSL、mTLS、GMS 等功能塞进 WebView 分支。
- 每个功能都要有 UI 入口、实机验证、失败排查和边界说明。
