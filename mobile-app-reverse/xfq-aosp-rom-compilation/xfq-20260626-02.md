## 正文

## 目标

把 APatch 做成 ROM 的一部分，而不是刷完机后再手工安装/授权：

- APatch Manager 随 ROM 预装到 `/product/app`。
- AOSP `boot.img` 在刷机前注入 KernelPatch/APatch payload。
- 首次打开 APatch 时使用 ROM 构建注入的默认 superkey 自动认证。
- AndroidPatch/APD 未安装或版本不匹配时自动安装。
- `adb shell` 默认进入 APatch/KP root shell。
- 默认 su 入口只使用 `/system/bin/su`，不再探测 `xu`/`xfu`/`kp`。

## Pixel 7 patch 目标

不要固定按“Pixel 7 就 patch init_boot”的文章来做。那类文章通常是 Magisk/ramdisk 语境。

APatch / KernelPatch 是 patch kernel，所以判断标准是：

```text
kptools unpack <image> 后是否产生 kernel
kptools -i kernel -f 是否包含 CONFIG_KALLSYMS=y
```

当前 panther AOSP out：

```text
boot.img      -> 有 kernel，可 patch
init_boot.img -> Kernel size: 0，不可 patch
```

因此当前 patch 目标是：

```text
out/target/product/panther/boot.img
```

正确工具组合：

```text
host tool = kptools-linux
payload   = kpimg-android
```

不要误用 `kpimg-linux`。之前误用后 supercall 能部分工作，但 Android 侧 `kp/sumgr/supercmd` 不完整。

## APatch 源码改动

### 1. 构建参数

`app/build.gradle.kts` 新增 ROM 构建参数：

```text
DEFAULT_SUPERKEY      # ROM 默认 superkey
AUTO_INSTALL_APATCH   # 首次打开是否自动安装/更新 APD
AUTO_INSTALL_MODULES  # 可选，逗号分隔模块路径
```

构建命令：

```bash
cd /home/xiaofeng/Desktop/projects/apatch
ANDROID_HOME=/home/xiaofeng/Android/Sdk ANDROID_SDK_ROOT=/home/xiaofeng/Android/Sdk \
  ./gradlew :app:assembleDebug \
  -PDEFAULT_SUPERKEY="xiaofeng777" \
  -PAUTO_INSTALL_APATCH="true" \
  -PAUTO_INSTALL_MODULES=""
```

当前使用 debug APK。release APK 如果没有 APatch 官方签名，会触发上游签名校验退出；实验 ROM 先用 debug APK 最稳。

### 2. 自动认证

`APatchApp.kt` 启动时按以下顺序设置 superkey：

```text
stored key -> BuildConfig.DEFAULT_SUPERKEY -> "su"
```

`DEFAULT_SUPERKEY` 验证通过后会自动写入本地 SharedPreferences，后续不需要用户输入。

### 3. 自动安装 APD

`Home.kt` 观察 AP 状态：

```text
ANDROIDPATCH_NOT_INSTALLED / ANDROIDPATCH_NEED_UPDATE
```

如果 `AUTO_INSTALL_APATCH=true`，自动调用：

```text
APApplication.installApatch()
```

安装内容：

```text
/data/adb/apd
/data/adb/ap/bin/apd -> /data/adb/apd
/data/adb/ap/bin/magiskpolicy -> /data/adb/apd
/data/adb/ap/bin/resetprop -> /data/adb/apd
/data/adb/ap/bin/busybox
/data/adb/ap/bin/kptools
/data/adb/ap/su_path
```

### 4. su path 策略

不要再把用户入口固定为 `/system/bin/kp`。

当前默认：

```text
/data/adb/ap/su_path = /system/bin/su
```

APatch root shell fallback 顺序：

```text
/system/bin/su -> PATH su -> sh
```

`kp`、`xu`、`xfu` 不再作为 APatch App 的 root shell 候选。

## ROM 内置步骤

### 1. 替换预装 APK

APatch APK 放在补丁仓：

```text
android13_r78_changes/preloads/apks/apatch/APatch.apk
```

从 APatch 构建产物复制：

```bash
cp /home/xiaofeng/Desktop/projects/apatch/app/build/outputs/apk/debug/APatch_11215_2c00671_main-debug.apk \
  /home/xiaofeng/Desktop/projects/aosp/android13_r78_changes/preloads/apks/apatch/APatch.apk
```

当前 APK sha256：

```text
e8bf6c21b514e6c397bfcb43227ebdc3ba2fc2a1cc183b014e8d7e54b948efed
```

### 2. manifest 条目

`preloads/manifest.json` 中 APatch 条目：

```json
{
  "id": "apatch-manager",
  "type": "apk",
  "src": "apks/apatch/APatch.apk",
  "package": "me.bmax.apatch",
  "profiles": ["apatch", "full"]
}
```

APatch Manager 作为普通 `/product/app` 安装，不放 priv-app，避免 user build 下 privapp permission enforcement 多一层风险。

### 3. 生成 AOSP 预装模块

```bash
cd /home/xiaofeng/Desktop/projects/aosp/android13_r78_changes
python3 tools/generate_xf_preloads.py --profile full --clean
```

生成到：

```text
android13_r78/external/xf_preloads/
```

生成器会保持 APK 原字节不变，并额外抽取 arm64 JNI libs 到 app-local lib 目录，避免 APatch `System.loadLibrary()` 找不到 so：

```text
/product/app/xf_preload_apk_apatch_manager/lib/arm64/libapjni.so
/product/app/xf_preload_apk_apatch_manager/lib/arm64/libapd.so
/product/app/xf_preload_apk_apatch_manager/lib/arm64/libbusybox.so
/product/app/xf_preload_apk_apatch_manager/lib/arm64/libkptools.so
...
```

### 4. patch boot.img

```bash
cd /home/xiaofeng/Desktop/projects/aosp/android13_r78_changes
python3 tools/patch_apatch_boot.py \
  --product-out /home/xiaofeng/Desktop/projects/aosp/android13_r78/out/target/product/panther \
  --replace \
  --out-dir /tmp/aosp-apatch-patched \
  --json /tmp/aosp-apatch-patched/result.json
```

`--replace` 会把 patched boot 覆盖回 AOSP out，供后续 `fastboot flashall` 使用。

### 5. 编译与刷机

```bash
cd /home/xiaofeng/Desktop/projects/aosp/android13_r78
source build/envsetup.sh
lunch aosp_panther-user
m -j10
```

刷机前确认 `boot.img` 已 patch，然后 full flash：

```bash
cd /home/xiaofeng/Desktop/projects/aosp/android13_r78/out/target/product/panther
ANDROID_PRODUCT_OUT="$PWD" fastboot -s 35051FDH2000NQ flashall
```

product-only 迭代只能更新 APK/预装内容；如果改了 adbd、system、boot 或 APatch root 链，走 full flash 更稳。

## adbd 默认 root

user build 下 `adb root` 强制不可用，这是预期。

为了让 `adb shell` 默认进 root，改的是 adbd shell fork 流程：

```text
/system/bin/su -> /system/bin/sh
```

对应 AOSP patch：

```text
patches/20260625-adbd-su-root-shell/packages_modules_adb.patch
```

注意：不再从 adbd 里探测 `kp`、`xu`、`xfu`，减少可识别 root 入口。

## 预装 demo / launcher 调整

预装机制已经支持 APatch、demo APK、bin 工具：

```text
preloads/apks/       -> /product/app/<id>/<apk>
preloads/priv-apps/  -> /product/priv-app/<id>/<apk>
preloads/bins/       -> /product/bin/<name>
preloads/etc/        -> /product/etc/xf-preloads/...
preloads/data-seed/  -> /product/etc/xf-preloads/data-seed/...
```

APatch Manager 从 `priv-app` 改成普通 `apk` 是有意的：user build 下普通 app 更少权限声明/签名约束，APD/root 能力由 patched boot + superkey 提供，不靠 priv-app 权限。

## 上游检查策略

不要在每次 AOSP 编译时自动查 GitHub 上游：

- AOSP build 应该可离线、可复现。
- GitHub 网络失败不能让普通 build 失败。
- 每次 fetch 会拖慢构建，也会引入不可控状态。

## 不要再踩的坑

- 不要把 APatch 的默认入口再改回 `/system/bin/kp`，也不要默认探测 `xu`/`xfu`。
- APatch APK 是本地 payload，大文件不建议进 `android13_r78_changes` Git；真正源码已推到 APatch fork。
- 如果将来要彻底改变 kpimg 编译时默认 `SU_PATH`，需要从 KernelPatch 源码重新编译 `kpimg-android`，不要再做简单二进制字符串替换。
- full `flashall` 会覆盖 boot；刷前要先 `patch_apatch_boot.py --replace`，或者刷后单独刷 patched boot。
- `init_boot.img` 当前不是 APatch/KP patch 目标，因为没有 kernel。

## 2026-06-26 更新：删除 kp/xu/xfu 候选

为减少 root 环境特征入口，APatch App 和 adbd 都只保留 `/system/bin/su`：

```text
APatch root shell: /system/bin/su -> PATH su -> sh
adbd shell:        /system/bin/su -> /system/bin/sh
```

已删除候选：

```text
/system/bin/kp
/system/bin/xu
/system/bin/xfu
```

代价：如果 userdata 被清掉且 APatch 尚未把 runtime su path 设置成 `/system/bin/su`，首次 `adb shell` 可能先落回普通 sh；打开 APatch 自动初始化后会恢复 `/system/bin/su` root 入口。
