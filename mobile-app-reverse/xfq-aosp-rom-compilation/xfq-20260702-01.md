## 0. 结论先写清楚

本功能已经完成并刷机验证：实验 ROM 内置 Pixel 7 原厂 `Pixel Launcher`，默认 HOME 指向
`com.google.android.apps.nexuslauncher/.NexusLauncherActivity`，并通过 product RRO 把 framework 的
Recents/QuickStep 组件切换到 Pixel Launcher，避免打开桌面时因为 `signature|recents` 权限未授予而崩溃。

已完成范围：

- 预置 `NexusLauncherRelease.apk`。
- 覆盖移除 AOSP `Launcher3/Launcher3QuickStep/Launcher3QuickStepGo` 作为内置桌面候选。
- 新增 `XfPixelLauncherFrameworkOverlay`，把 `config_recentsComponentName` 指向 Pixel Launcher 的 Recents。
- 实机验证 HOME 可打开，不再出现 `MANAGE_ACTIVITY_TASKS` 权限崩溃。

未完成/不属于本功能范围：

- Pixel 默认壁纸、动态壁纸、壁纸选择器、主题包、At a Glance 完整体验。
- 因此刷完后“桌面是 Pixel Launcher”，但壁纸仍可能是 AOSP/旧 userdata 的壁纸；这不是本功能失败。
- 如果要 Pixel 原厂视觉效果，需要单独做 `feature/pixel-wallpaper-preload`。

## 3. 构建规则改动

### 3.1 `Android.mk`: 定义预置 APK

文件：`vendor/xf_gms/panther/Android.mk`

现有宏 `xf-gms-prebuilt-priv-app` 被扩展了第 4 个参数，用来设置 override：

```make
$(if $(strip $(4)),LOCAL_OVERRIDES_PACKAGES := $(4))
```

Pixel Launcher 规则：

```make
$(eval $(call xf-gms-prebuilt-priv-app,NexusLauncherRelease,system_ext/priv-app/NexusLauncherRelease/NexusLauncherRelease.apk,system_ext,Launcher3 Launcher3QuickStep Launcher3QuickStepGo))
```

含义：

- `LOCAL_MODULE := NexusLauncherRelease`
- `LOCAL_SRC_FILES := system_ext/priv-app/NexusLauncherRelease/NexusLauncherRelease.apk`
- `LOCAL_SYSTEM_EXT_MODULE := true`
- `LOCAL_PRIVILEGED_MODULE := true`
- `LOCAL_CERTIFICATE := PRESIGNED`
- `LOCAL_OVERRIDES_PACKAGES := Launcher3 Launcher3QuickStep Launcher3QuickStepGo`

这样安装 `NexusLauncherRelease` 时，会把 AOSP 内置 `Launcher3*` 桌面候选从最终镜像里移除。

### 3.2 `gms.mk`: 加入 PRODUCT_PACKAGES

文件：`vendor/xf_gms/panther/gms.mk`

只在本地 payload 存在时启用：

```make
ifneq (,$(wildcard $(XF_GMS_ROOT)/system_ext/priv-app/NexusLauncherRelease/NexusLauncherRelease.apk))
XF_GMS_PACKAGES += NexusLauncherRelease
XF_GMS_PACKAGES += XfPixelLauncherFrameworkOverlay
endif
```

注意 `XfPixelLauncherFrameworkOverlay` 也绑定在同一个条件下，否则没有 Pixel Launcher 时不应该改 framework Recents 指向。

## 4. 为什么还需要 framework Recents RRO

第一次只装 Pixel Launcher 后，HOME 能 resolve 到 Pixel Launcher，但打开会崩：

```text
java.lang.SecurityException: Permission Denial: getRootTaskInfo()
requires android.permission.MANAGE_ACTIVITY_TASKS
```

根因：

- Pixel Launcher 请求了多项 `signature|recents` 权限。
- 这些权限不是普通 privapp XML 写上就一定会给。
- framework 会根据 `config_recentsComponentName` 判断“谁是 Recents/QuickStep provider”。
- AOSP 默认值仍是：

```text
com.android.launcher3/com.android.quickstep.RecentsActivity
```

所以系统没有把 `MANAGE_ACTIVITY_TASKS`、`MONITOR_INPUT`、`READ_FRAME_BUFFER`、`GET_TOP_ACTIVITY_INFO` 等权限授给
`com.google.android.apps.nexuslauncher`，导致 Pixel Launcher 启动时崩溃。

### 4.1 修复方式：新增 product RRO

新增目录：

```text
vendor/xf_gms/panther/pixel_launcher_framework_overlay/
├── AndroidManifest.xml
└── res/values/config.xml
```

`AndroidManifest.xml`：

```xml
<manifest xmlns:android="http://schemas.android.com/apk/res/android"
    package="com.xiaofeng.frameworkres.overlay.pixellauncher">
    <application android:hasCode="false" />
    <overlay
        android:targetPackage="android"
        android:isStatic="true"
        android:priority="900" />
</manifest>
```

`res/values/config.xml`：

```xml
<resources>
    <string name="config_recentsComponentName" translatable="false">com.google.android.apps.nexuslauncher/com.android.quickstep.RecentsActivity</string>
</resources>
```

### 4.2 为什么不用 `device/google/pantah/panther/overlay/...`

试过改 Panther 的 static vendor overlay：

```text
device/google/pantah/panther/overlay/frameworks/base/core/res/res/values/config.xml
```

但当前工程里 `vendor.img` 主要是预编译 copy，改这个 overlay 不会稳定进最终刷机镜像。
因此最终改为 **product RRO**，跟 GMS/Pixel Launcher 一起走 `vendor/xf_gms/panther`，可控且容易验证：

```text
/product/overlay/XfPixelLauncherFrameworkOverlay.apk
```

## 10. 常见问题

### 10.1 桌面是 Pixel Launcher，但壁纸不是 Pixel 默认？

正常。本功能只做 Pixel Launcher/QuickStep，不包含 Pixel 壁纸体系。

Pixel 默认视觉至少还需要另一个功能分支处理：

```text
PixelWallpapers2022
PixelLiveWallpaperPrebuilt
WallpaperPicker / Google Wallpapers
PixelThemes / ThemePicker
默认壁纸 overlay 或首次启动初始化
```

建议新分支：

```text
feature/pixel-wallpaper-preload
```

### 10.2 `get_build_var PRODUCT_PACKAGES` 还能看到 `Launcher3QuickStep` 是不是失败？

不一定。`PRODUCT_PACKAGES` 只是产品变量，最终安装阶段会根据 `LOCAL_OVERRIDES_PACKAGES` 处理覆盖。
判断是否成功看：

```bash
grep Launcher3QuickStep out/target/product/panther/installed-files-system_ext.txt
adb -s 35051FDH2000NQ shell pm path com.android.launcher3
```

这两个都不应该显示 `Launcher3QuickStep.apk`。

### 10.3 Pixel Launcher 打开崩溃怎么查？

优先看权限：

```bash
adb -s 35051FDH2000NQ shell \
  'dumpsys package com.google.android.apps.nexuslauncher | sed -n "/install permissions:/,/User 0:/p" | grep -E "MANAGE_ACTIVITY_TASKS|granted=false"'
```

如果 `MANAGE_ACTIVITY_TASKS: granted=false`，检查 RRO 是否安装：

```bash
adb -s 35051FDH2000NQ shell pm path com.xiaofeng.frameworkres.overlay.pixellauncher
```

如果 RRO 不存在，说明 `XfPixelLauncherFrameworkOverlay` 没进 product.img 或没刷 product/vbmeta。

### 10.4 为什么不用 `cmd role holders android.app.role.HOME`？

当前 Android 13 设备上的 `cmd role` 子命令并不支持 `holders/get-role-holders`，实际命令会返回 `Unknown command`。
本功能验收使用：

```bash
cmd package resolve-activity --brief -a android.intent.action.MAIN -c android.intent.category.HOME
```
