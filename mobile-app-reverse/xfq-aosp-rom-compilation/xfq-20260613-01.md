## 问题

1. **Captive Portal 误报**：即使 Wi-Fi 能正常上网，状态栏长期显示 "Checking for internet..." 或 "Limited connection"
2. **开机不自动连 Wi-Fi**：Wi-Fi 不会在开机后自动连接已保存的网络
3. **Wi-Fi 被禁用**：因 captive portal 反复验证失败，系统将 Wi-Fi 网络标记为 disabled，导致完全不连接

## 根因

### Captive Portal 误报

AOSP NetworkStack 默认探测地址是 Google 的服务器：

```
default_captive_portal_http_url  → http://connectivitycheck.gstatic.com/generate_204
default_captive_portal_https_url → https://www.google.com/generate_204
```

这些地址在国内不可达。探测失败后 NetworkMonitor 将网络标记为 `PARTIAL` / `CAPTIVE_PORTAL`，状态栏显示"Limited connection"。

### AOSP 已有但无效的机制

AOSP 为 MCC 460（中国区 SIM 卡）提供了备用配置：

```
packages/modules/NetworkStack/res/values-mcc460/config.xml
→ http://connectivitycheck.gstatic.cn/generate_204
→ https://connectivitycheck.gstatic.cn/generate_204
```

但这**仅在插入中国 SIM 卡时自动加载**。Pixel 7 研究机不插 SIM 卡，所以此配置从未生效。

### Wi-Fi 被禁用的机制

Android Wi-Fi 框架在以下情况下会禁用已保存的网络：
1. 网络验证（captive portal）反复失败
2. 系统将网络标记为 `disabled SSID`
3. 自动连接不会尝试已禁用的网络
4. 用户必须手动在设置里重新点击连接

## 解决方案

### 方案尝试过程

| 方案 | 结果 | 原因 |
|------|:----:|------|
| ① Device Product Overlay (`DEVICE_PACKAGE_OVERLAYS`) | ❌ 无效 | NetworkStack 是 mainline 模块，product overlay 的 RRO 未被加载 |
| ② ADB 临时设置 | ✅ 临时可用 | `settings put global` 重启后仍有效，但不是默认行为 |
| ③ **直接修改 NetworkStack 源码** | ✅ **永久有效** | 修改 `config.xml` 默认 URL + `NetworkStackUtils.java` 硬编码常量 |

### 最终采用方案：③ 直接修改源码

#### 修改的文件

**1. `packages/modules/NetworkStack/res/values/config.xml`**

```xml
<!-- 修改前 -->
<string name="default_captive_portal_http_url">http://connectivitycheck.gstatic.com/generate_204</string>
<string name="default_captive_portal_https_url">https://www.google.com/generate_204</string>

<!-- 修改后 -->
<string name="default_captive_portal_http_url">http://connectivitycheck.gstatic.cn/generate_204</string>
<string name="default_captive_portal_https_url">https://connectivitycheck.gstatic.cn/generate_204</string>
```

**2. `packages/modules/NetworkStack/src/android/net/util/NetworkStackUtils.java`**

```java
// 修改前
public static final String[] DEFAULT_CAPTIVE_PORTAL_HTTP_URLS =
    new String[] {"http://connectivitycheck.gstatic.com/generate_204"};
public static final String[] DEFAULT_CAPTIVE_PORTAL_HTTPS_URLS =
    new String[] {"https://www.google.com/generate_204"};

// 修改后
public static final String[] DEFAULT_CAPTIVE_PORTAL_HTTP_URLS =
    new String[] {"http://connectivitycheck.gstatic.cn/generate_204"};
public static final String[] DEFAULT_CAPTIVE_PORTAL_HTTPS_URLS =
    new String[] {"https://connectivitycheck.gstatic.cn/generate_204"};
```

#### 探测优先级（修改后）

```
优先级 1: Settings.Global (ADB 运行时修改)        → 无（已清除）
优先级 2: config_captive_portal_* (RRO overlay)   → 无（空值）
优先级 3: default_captive_portal_* (config.xml)    → http://connectivitycheck.gstatic.cn/generate_204
优先级 4: DEFAULT_CAPTIVE_PORTAL_* (硬编码)        → http://connectivitycheck.gstatic.cn/generate_204
```

#### Fallback URL（备选探测地址）

当主探测失败时，依次尝试以下 fallback URL：

```
http://connectivitycheck.gstatic.com/generate_204   ← 国际备选
http://www.google.com/gen_204                        ← 国际备选
http://play.googleapis.com/generate_204              ← 国际备选
```

## 编译与刷机

### 编译目标

```bash
m NetworkStack ROMManager privapp-permissions-com.xiaofeng.rommanager.xml systemimage productimage -j16
```

需要同时编译 `systemimage`（NetworkStack 在 system 分区）和 `productimage`（ROMManager 在 product 分区）。

### 刷机

```bash
fastboot flash system system.img
fastboot flash product product.img
fastboot reboot
```

**注意**：只刷 `product.img` 不够，因为 NetworkStack 在 system 分区。

### 验证方法

```bash
# 手动连接 Wi-Fi 后
adb shell dumpsys connectivity | grep -E "VALIDATED|CAPTIVE|PARTIAL"

# 查看 NetworkMonitor 日志
adb logcat -b main -s NetworkMonitor
```
