## 正文

## 目标

基于 Pixel 7 Panther 原厂 image 提取 GMS 组件，内置到当前 AOSP ROM。专有 payload 只保存在本机 AOSP 构建树，不进入 GitHub 补丁仓库。

## 需求介绍

这个需求的目标是把 Pixel 7 原厂 GMS 套件以“本地可复现、仓库不分发专有 payload”的方式内置到当前 AOSP ROM。它不是简单把 APK 丢进仓库：GMS 文件来自原厂 image，属于本机私有 payload，GitHub 只能保存提取脚本、构建规则、文件清单和校验信息。

要解决的问题：

- AOSP 默认不带 Google Play 服务，很多真实 App/测试场景缺少 GMS 环境。
- 直接提交 Google APK 不合适，也会让补丁仓库变得不可公开维护。
- GMS 涉及 `product`、`system_ext`、priv-app、permission allowlist，放错分区会导致扫描失败或特权权限异常。
- 后续 Pixel Launcher 也依赖同一个原厂 payload 目录，因此 GMS 提取机制要可扩展。

## 调研结论

调研原厂 Pixel 7 image 后，核心 GMS 分布如下：

| 组件 | 原厂分区 | 目标路径 | 作用 |
|---|---|---|---|
| `PrebuiltGmsCoreSc.apk` | `product` | `/product/priv-app/PrebuiltGmsCore/` | Google Play services |
| `Phonesky.apk` | `product` | `/product/priv-app/Phonesky/` | Play Store |
| `GoogleServicesFramework.apk` | `system_ext` | `/system_ext/priv-app/GoogleServicesFramework/` | GSF 基础框架 |

同时确认：`oat/odex/vdex/art/dm` 这类预优化/签名状态相关文件不应该直接复用到当前 AOSP 构建，提取脚本要剔除，避免 ABI/签名/预优化状态不一致。

## 方案取舍

| 方案 | 优点 | 缺点 | 结论 |
|---|---|---|---|
| 直接把 GMS APK 提交到 GitHub | 构建最省事 | 专有 payload 进仓库，不可接受 | 不采用 |
| 手动复制到 out 目录 | 临时能刷 | 不可复现，clean build 失效 | 不采用 |
| 从原厂 image 提取到本机 `vendor/xf_gms/panther/{product,system_ext}` | 可复现，payload 不进仓库 | 首次需要准备 factory image | 采用 |
| 写死 `PRODUCT_COPY_FILES` 不做存在判断 | 规则简单 | payload 缺失时构建失败 | 不采用 |
| `inherit-product-if-exists` + payload 存在才启用 | 对公开仓库友好 | 需要提取脚本/README 说明 | 采用 |

## 优缺点与边界

优点：

- 构建逻辑可重复，换机器只要准备同版本 factory image 再提取即可。
- GitHub 仓库不携带专有 APK/JAR/XML payload。
- GMS 路径保持原厂分区语义，便于后续 Play Store/GMS 行为测试。

边界：

- 本功能只解决 GMS 预置，不保证账号登录、SafetyNet/Play Integrity、认证设备状态。
- 无 wipe 刷机时可能保留旧 userdata 包状态，验证时要区分系统镜像问题和用户数据污染。
- Pixel Launcher、壁纸、主题等属于后续功能，不应该混进 GMS 基础套件结论里。

## 实现

- 新增 `vendor/xf_gms/panther/` 构建入口：
  - `Android.mk`：定义 PRESIGNED 预置 APK / GMS Chimera module 数据文件。
  - `gms.mk`：只在本地 payload 存在时加入 `PRODUCT_PACKAGES` / `PRODUCT_COPY_FILES`。
  - `extract_panther_gms.sh`：从 factory image / inner image zip 提取 `product.img` 与 `system_ext.img` 里的 GMS 文件，去掉 oat/odex/vdex/art/dm，生成清单与校验和。
  - `.gitignore`：忽略本地 `product/`、`system_ext/` payload。
- `device/google/pantah/aosp_panther.mk` 增加：
  ```make
  $(call inherit-product-if-exists, vendor/xf_gms/panther/gms.mk)
  ```

### 7. 常见失败点

- 编译报重复目标：先检查 `system_ext/etc/permissions/com.google.android.iwlan.xml` 是否被提取进来了；本方案刻意排除了它。
- 开机 fatal privapp allowlist：用下面命令定位缺哪个 permission，再补 allowlist：

```bash
adb -s "$PIXEL7_SERIAL" logcat -d | grep -iE 'Privileged permission|privapp|GoogleServicesFramework|PrebuiltGmsCore|Phonesky'
```

- Play Store 打不开：先确认不是 userdata 旧包状态污染。无 wipe 刷机时可能存在旧 `packages.xml` 噪声，必要时只清目标包数据，不要默认 wipe 全机：

```bash
adb -s "$PIXEL7_SERIAL" shell pm clear com.android.vending
adb -s "$PIXEL7_SERIAL" shell pm clear com.google.android.gms
```
