## 正文

## 需求

user 版本默认仍开启 USB adb，但不弹 RSA 授权确认；目标是这套 build 策略对 Pixel 7 / Pixel 5 等产品通用，而不是只改 panther 产品配置。

## 根因

AOSP user 构建的 RSA 授权来自通用 build core：

```make
# build/make/core/main.mk
ifeq ($(user_variant),user)
  ADDITIONAL_SYSTEM_PROPERTIES += ro.adb.secure=1
endif
```

之前只在产品配置里加 `ro.adb.secure=0` 会和 core 的 `ro.adb.secure=1` 重复，user build 的 build.prop 校验会失败。

## 改动

已在构建树改为：

```make
ADDITIONAL_SYSTEM_PROPERTIES += ro.adb.secure=0
```

说明：

- 这是 build core 级改动，不是 panther-only，所以同一棵 AOSP 树里的 Pixel 7 / Pixel 5 user build 都会继承。
- 只去掉 adb RSA 授权弹窗；不等于 `adb root`。
- user build 仍保持：`ro.secure=1`、`ro.debuggable=0`，所以 `adbd cannot run as root in production builds` 仍是预期行为。
- `device/google/pantah/aosp_panther.mk` 的 `ro.adb.secure=0` 继续只保留给非 user 变体，避免 user build 重复 sysprop。
