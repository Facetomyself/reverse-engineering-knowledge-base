## 一、整体目标

让 Reqable（及其它用户 CA）证书在 Pixel 7 / panther AOSP ROM 中被系统信任，覆盖两类来源：

1. **内嵌 ROM 的 CA**（编译期）——已通过 `cacerts_xf` 模块实现，证书随 `/system/etc/security/cacerts/` 一起打包。
2. **用户运行时新增的 CA**（运行期）——ROMManager 写入 `/data/misc/xf_cacerts/added/`，开机由 init bind-mount 合并进系统证书目录。

## 二、Part 1：内嵌 Reqable CA（编译期）

### `system/ca-certificates/xf/`
- `Android.bp` — `cacerts_xf` 模块，装到 `/system/etc/security/cacerts/`。
- `files/d8e119df.0` — **Reqable CA**（桌面 `reqable-ca.crt` 转换而来）。
  - `subject_hash_old = d8e119df`，与文件名一致（Android 按此 hash 查找证书，**必须匹配**）。
  - 主体：`O = Reqable, LLC / CN = Reqable CA (Jun 14, 2026, DBB3248A)`。
  - 有效期：`2026-06-14 .. 2033-05-31`，`CA:TRUE`，`Certificate Sign`。
- `scripts/pem_to_cacert.sh` — 任意 PEM → AOSP `.0`（`openssl x509 -subject_hash_old` 命名）。

### `device/google/pantah/aosp_panther.mk`
`PRODUCT_PACKAGES += cacerts_xf ROMManager privapp-permissions-... xf_cert_prep`

## 四、Part 3：开机注入基础设施（运行期用户 CA）⭐ 核心难点

### 为什么不能简单地写 `/system/etc/security/cacerts/`
Android 13 SELinux 有两条**硬性 neverallow**（`system/sepolicy/public/domain.te`），直接否决了"准备目录→打标签→替换"的常规思路：

| 行号 | neverallow | 含义 |
|------|-----------|------|
| `domain.te:560` | `neverallow { domain -init -otapreopt_chroot } { system_file_type ... }:dir mounton;` | **只有 init 本身**能在 `system_file_type`（即 cacerts 目录）上做 bind-mount。自定义域不行。 |
| `domain.te:510` | `neverallow { domain -kernel ... } { system_file_type vendor_file_type exec_type }:relabelto;` | **除 kernel 外谁都不能** relabel 成 `system_security_cacerts_file`。所以"准备目录→restorecon 成 cacerts 标签→挂载"被禁止。 |

### 因此采用的设计（唯一合规路径）
```
post-fs-data:
  init 创建 /data/misc/xf_cacerts/{added,store}
  init exec_start xf_cert_prep        # 阻塞直到脚本退出
    └─ xf_cert_prep 域（coredomain）: 把 系统 cacerts/* + added/*.0 复制进 store/
  init mount none .../store /system/etc/security/cacerts bind rec   # 只有 init 能挂
```
- bind-mount **保留源标签**，所以挂载后 cacerts 路径下的文件标签是 `xf_cacerts_data_file`。
- 该标签是 `core_data_file_type`。**只授予 `coredomain` + `appdomain` 读权限**（真正的证书消费者：system_server、浏览器/Reqable 等 app）。
  - ⚠️ **不能写 `allow domain ...`**：`domain` 含 vendor 域（`hal_*`/`rild`/`chre`...），而 `domain.te:824` 一族 neverallow 禁止 vendor 域访问任何 `core_data_file_type`。
  - `zoneinfo_data_file` 之所以能全域可读，是因为它在 6 个文件、约 14 处 vendor neverallow 里都被 `-zoneinfo_data_file` 显式豁免。仿它需要维护这一整套豁免，非常脆弱。
  - 改为只给 `{ coredomain appdomain }`：正好落在 neverallow 824 的豁免主体集 `{ -appdomain -coredomain -vendor_init }` 之外，**无需任何 carve-out**。这是编译实测（294 个 neverallow 失败）后定位并修正的设计。

### 涉及文件
| 文件 | 改动 |
|------|------|
| `system/extras/xf_cert_prep/xf_cert_prep.sh` | 合并脚本：清空 store → 复制系统证书 → 叠加 `added/*.0` → 修权限 |
| `system/extras/xf_cert_prep/Android.bp` | `sh_binary { name: "xf_cert_prep", init_rc: [...] }` |
| `system/extras/xf_cert_prep/xf_cert_prep.rc` | `service xf_cert_prep ... oneshot disabled seclabel u:r:xf_cert_prep:s0` |
| `system/core/rootdir/init.rc` | `on post-fs-data` 末尾：建目录 + `exec_start xf_cert_prep` + `mount ... bind` |
| `system/sepolicy/public/file.te` | `type xf_cacerts_data_file, ...` |
| `system/sepolicy/private/file_contexts` | `/data/misc/xf_cacerts(/.*)?` + `/system/bin/xf_cert_prep` exec 标签 |
| `system/sepolicy/private/xf_cert_prep.te` | 新域，仿 `cppreopts.te`：`init_daemon_domain` + `shell_exec`/`toolbox_exec` rx + 读系统证书 + 读写 staging |
| `system/sepolicy/public/domain.te` | `allow { coredomain appdomain } xf_cacerts_data_file:{file,dir} r_*`（仅核心域+应用域可读） |
| `system/sepolicy/public/init.te` | `allow init system_security_cacerts_file:dir mounton`（init 才能挂 cacerts） |
| `system/sepolicy/private/priv_app.te` | `allow priv_app xf_cacerts_data_file:{dir,file} create_*`（ROMManager 写 staging） |

### sepolicy 冻结测试（关键约束！）
- android13_r78 是 **REL** 版本（`PLATFORM_VERSION_CODENAME.TP1A := REL`），故 `PLATFORM_SEPOLICY_VERSION = 33.0 ≠ 10000.0 = TOT`。
- 触发 `se_freeze_test`：对 `public/`、`private/` 与 `prebuilts/api/33.0/{public,private}/` 做 **`diff -r -q`**，任何差异即失败。
- 因此**所有上述 sepolicy 改动都同步复制了一份到 `prebuilts/api/33.0/` 对应文件**，否则编译报冻结测试失败。

### ⭐ sepolicy 调通踩坑链（真实编译逐轮定位，非臆测）
| 轮次 | 改动 | 失败数/现象 | 根因 |
|------|------|------------|------|
| 1 | `allow domain xf_cacerts_data_file` | 294 neverallow | `domain` 含 vendor 域，撞 `domain.te:824`「vendor 不准碰 core_data_file_type」 |
| 2 | 收窄 `{coredomain appdomain}` | 11 neverallow | ① `traced/perfetto/traced_probes/mediaextractor`（coredomain）有「只准 zoneinfo」私有 neverallow；② `xf_cert_prep` 用了不在 `dac_override_allowed` 白名单的 capability |
| 3 | 收窄 `{system_server appdomain}` + 删 capability + 删脚本多余 chown | Treble 测试失败 | `xf_cacerts_data_file` 是 **public type**，缺 `private/compat/V.v` 映射条目 |
| 4 | 类型 public→**private**（`public/file.te`→`private/file.te`） | `pub_policy.cil` 编译失败 `unknown type` | `public/domain.te` 引用了已变 private 的类型 |
| 5 | 把 allow 块 `public/domain.te`→`private/domain.te` | **✅ 成功** | — |

**核心教训**：
- 给 `/data` 文件发跨域读权限，主体绝不能用 `domain`（含 vendor）；按真实消费者收窄到 `{system_server appdomain}`。
- 仿 `zoneinfo` 全域可读的代价是 6 文件 ~14 处 neverallow carve-out，不值得；收窄主体可完全避开。
- 只被 system 侧引用的类型应放 `private/`（不受 Treble compat 映射约束）；其所有 allow 规则也必须同在 `private/`。
- root 域自建目录无需 `dac_override`/`chown`（参考 `cppreopts` 零 capability）。
- 每改一处 sepolicy 都要同步 `cp` 到 `prebuilts/api/33.0/` 对应文件（REL 版冻结测试 `diff -r`）。
