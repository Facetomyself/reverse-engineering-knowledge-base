xfqtrace v2.0：快速/稳定/全面/隐藏
最近一两个月又是考试又是写工具的，说实话压力真的非常大，不过好在做的差不多了，希望对大家有用吧。
** 不会用的安装skill让：pip install xfqtrace-skills,然后让ai看skills自动安装就好了，不然感觉我得说很多废话还得科普一堆hhh
** 要抹特征需要apatch加载kpm,其他root管理器请自行解决，暂不考虑适配
下面列一点相对1.3的一些更新
1. 隐藏：使用gozinject的fork版xfinject，然后修了一些bug, 再搭配我写的xfvmahide.kpm模块，可以隐藏掉注入特征还有异常maps特征; 2.1版本预计会针对性的检测开源的trace工具，然后在我们的这一套工具中 动态抹掉特征，敬请期待;
2. 更稳定了，之前星友反馈的设备问题，还有其他我代码的问题如find jni我都改了，如果还是不行请反馈给我;
3. 全面：真正trace时需要的各种定制功能基本上都覆盖了;
3.0 搞了个skill,帮你自动化trace啥的，有点用但不多hhh（这个是橙佬提供的想法还有代码参考，不过我做的很轻量）
3.1 hook_format 支持解析函数参数类型，这样你trace到的可以知道入参返回值，不需要再来个hook引入特征; 而且我还解析了java数据类型，如字符串，jset jbarr, jlist jmap; 这一点对于传入容器然后native函数在容器中塞了数据的很有用哦，还可以jmap.diff可以对比前后的map变化，非常好用！
3.2 支持高级过滤 filter_expr/filter_sql ：类似sql写法，比如我们trace的时候想要固定一组数据怎么办，只能被动trace+主动frida调用么，那如果样本自身触发很频繁就会很卡，所以这里过滤了入参，支持各种数据类型，配合主动调用可以精确拦截某一次trace;
  filter_expr: `x3:jbarr contains hex('${asciiHex(TRACE_MARKER)}')`,
filter_sql: "where jbarr(x2) contains_hex '68747470733a2f2f6d616c6c2e73686f7065652e766e2f6170692f76342f6e61746976652f686f6d6570616765'"
这里感谢塔佬的想法，这个确实是很常用的一个功能，但是1.3没想着做，然后2.0把这个做好了发出来，非常好用！
具体可以看skill和压缩包中的usage.md,然后自己跑一下
3.3 排除范围 exclude_ranges：工具类函数如果已经分析出来了，还要继续trace的话，量级很大，不适合分析，这里提供底层的过滤功能; 后续版本可能会考虑做的更方便一些
还有很多功能，如果不会用看一下skill还有usage.md 如果没有你要的，请私信我
