1.5. 为什么std::string这么复杂
```

C++的std::string不是简单的字符数组,而是一个智能对象:
1. 自动内存管理 - 不需要手动malloc/free
2. 动态扩容 - 可以随时append
3. 性能优化 - SSO避免小字符串的堆分配
4. 安全性 - 自动管理长度,防止溢出
3
但这些优点在逆向时变成了复杂性:
●
需要理解内部结构
●
需要区分长短字符串
●
需要正确解引用指针

## 1.6. 基本概念

```
1. GCC/libstdc++ (Linux/Android常用)
2. LLVM/libc++ (macOS/iOS常用)
```

3. MSVC (Windows)

Android NDK通常使用 libc++ 或 libstdc++。

# 2. 常见实现方式

2.1. libc++ 实现(Android常用)

### 2.1.1. SSO (Small String Optimization)

libc++使用SSO优化,根据字符串长度有两种存储方式:
短字符串模式 (≤22字节,64位系统)

```
1
2
3
4
5
Offset  Size  Field
0x00    1     __is_long (最低位=0表示短字符串)
0x01    1     __size (字符串长度)
0x02    22    __data (内联存储的字符串内容)
总大小: 24字节
```

长字符串模式 (>22字节)
4

```
1
2
3
4
5
Offset  Size  Field
0x00    8     __cap (容量,最低位=1表示长字符串)
0x08    8     __size (字符串长度)
0x10    8     __data (指向堆内存的指针)
总大小: 24字节
```

### 2.1.2. 内存布局示例

短字符串 "Hello":

```
1
2
3
0x00: 0a 00 00 00 00 00 00 00  // size=5 (0x05<<1 | 0 = 0x0a)
0x08: 48 65 6c 6c 6f 00 00 00  // "Hello\0"
0x10: 00 00 00 00 00 00 00 00  // 未使用
```

长字符串 (>22字节):

```
1
2
3
0x00: 21 01 00 00 00 00 00 00  // capacity (0x121 = 289, 最低位=1)
0x08: 1e 01 00 00 00 00 00 00  // size = 286 (0x11e)
0x10: 40 e1 39 12 00 00 00 00  // data pointer = 0x1239e140
2.2. libstdc++ 实现(GCC)
2.2.1. Copy-on-Write (旧版本)
```

旧版libstdc++使用引用计数:

```
1
2
3
Offset  Size  Field
0x00    8     __data (指向字符串数据的指针)
总大小: 8字节 (只存指针)
```

实际数据在堆上:

```
[refcount][length][capacity][string_data\0]
1
2.2.2. 新版本 (C++11后)
```

新版libstdc++也使用SSO,但阈值不同(通常是15字节)。

## 3.1. 从unidbg输出分析

一个unidbg案例(微博 绿洲 oasis的签名参数,案例来源于龙哥文章,纯算过程中发现的)中dump的内存:

1

0x08: 1e 01 00 00 00 00 00 00  // 0x11e = 286 (size)
0x10: 40 e1 39 12 00 00 00 00  // 0x1239e140 (data pointer)
```

解析:
1.

```
0x121 & 1 = 1﻿ → 长字符串模式
```

2.

```
capacity = 0x121 >> 1 = 144﻿ (实际容量)
```

3.

```
size = 0x11e = 286﻿ 字节
```

4.

```
data = 0x1239e140﻿ → 真正的字符串内容在这个地址
```

// 长字符串:读取size和data指针
long size = ByteBuffer.wrap(header, 8, 8)
.order(ByteOrder.LITTLE_ENDIAN).getLong();
long dataPtr = ByteBuffer.wrap(header, 16, 8)
.order(ByteOrder.LITTLE_ENDIAN).getLong();
// 从data指针读取实际内容
byte[] content = emulator.getBackend().mem_read(dataPtr, (int)size);
String str = new String(content, StandardCharsets.UTF_8);
} else {
// 短字符串:直接从offset 1读取
int size = (header[0] & 0xFF) >> 1;
String str = new String(header, 1, size, StandardCharsets.UTF_8);
}

```
1. 地址不是std::string对象
```

○

○
需要根据函数签名判断

○

# 5. 总结

## 5.1. 关键点

1. std::string大小固定为24字节(64位系统)
2. 通过最低位判断长短字符串
3. 短字符串内联存储,长字符串存指针
4. 读取时先判断类型,再提取内容

## 5.2. 最佳实践

1. 封装统一的读取函数
2. 添加边界检查和异常处理
3. 根据实际SO库选择正确的解析方式
4. 在hook中验证读取结果的合理性
