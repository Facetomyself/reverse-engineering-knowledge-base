## 一、需求背景

目标是在 ROM 里内置一个通用 SO 注入基座，让后续逆向功能可以不用每次依赖 Frida 手工 attach。

本次先接入两个能力：

1. **xfinject SO 注入基座**  
   提供一个高级入口，可以按 allowlist payload id 或手机 SO 路径，手动提交一次注入 request。

2. **Arsylk/jnilog 作为 jnitrace 入口**  
   把 `libjnilog.so` 作为内置 payload，做成 ROMManager 里的 App 级持久开关。打开某个 App 的开关后，该 App 后续每次启动前由 framework 触发 xfinject，等待目标进程 fork 后注入 jnilog。

期望链路：

```text
ROMManager App 详情页打开 jnilog 开关
  -> persist.rommgr.app.<pkg>.xfinject_jnilog=1
  -> system_server / ActivityManager 在目标 App 启动前写 xfinject request
  -> init oneshot root service 启动 /product/bin/xfinjectd
  -> xfinjectd 等待目标 App fork
  -> 通过 zygote-trap 注入 /product/lib64/xfinject/libjnilog.so
  -> JniLog 输出目标 native so 的 JNI 调用
```

## 二、设计边界

### 2.1 xfinject 和 jnilog 的 UI 语义分开

这次明确区分两个入口：

| 分组 | 入口 | 语义 |
| --- | --- | --- |
| `xfinject` | `xfinject SO 注入` | 高级手动页；进入页面没有副作用，只有点击按钮才提交一次 request。 |
| `Trace` | `jnitrace:rom内置版` | 原 ROM/ART 内置 jnitrace 开关，使用 `jni_trace` 配置。 |
| `Trace` | `jnitrace:Arsylk/jnilog` | App 级持久开关；打开后该 App 后续每次启动都会注入 jnilog。 |

高级页文案必须表达清楚：

```text
此页不会自动注入；只有点击下面按钮才会手动提交一次 request。
持久 jnitrace 请使用 TRACE 分组开关。
```

### 2.2 framework 不直接 load jnilog

framework 侧不做：

```java
System.loadLibrary("jnilog")
```

它只负责在目标 App 启动前写 request，并启动 init oneshot service。真正注入由 `/product/bin/xfinjectd` 完成。

### 2.3 payload 不维护本地 fork 源码

ROM 只内置 release 产物和 allowlist，不在 AOSP changes 仓库维护 xfinject / jnilog 源码副本。

## 四、关键实现

### 4.1 ROMManager 功能声明

`FeatureCatalog.java` 中新增：

```java
new Feature("xfinject", "xfinject SO 注入",
        "高级注入：按 allowlist payload id 或手机 SO 路径提交 request", Category.XFINJECT, true),
new Feature("jni_trace", "jnitrace:rom内置版",
        "ROM/ART 内置 jnitrace 开关", Category.TRACE, true),
new Feature("xfinject_jnilog", "jnitrace:Arsylk/jnilog",
        "打开后每次启动该 App 都通过 xfinject 注入 libjnilog.so", Category.TRACE, true),
```

`RomConfig.java` 把 `xfinject_jnilog` 纳入 property-backed App 开关：

```java
private static boolean isPropertyBackedAppFeature(String key) {
    return "java_trace".equals(key)
            || "jni_trace".equals(key)
            || "xfinject_jnilog".equals(key)
            || "arm64_trace".equals(key);
}
```

### 4.2 framework 启动前布置 request

`ProcessList.java` 在普通 zygote 启动分支、`Process.start(...)` 之前检查：

```text
persist.rommgr.app.<pkg>.xfinject_jnilog
```

为 `1` 时写入 autostart request，并启动：

```text
ctl.start=xfinject_autostart
```

request 核心字段：

```json
{
  "package": "<pkg>",
  "payload_ids": ["jnilog"],
  "backend": "zygote-trap",
  "force_stop": false,
  "wait_for_launch": true,
  "hide": {
    "enabled": true,
    "mode": "kpm",
    "clear_before": true
  }
}
```

### 4.3 init service

`xfinject_request.rc` 保留两个 oneshot service：

```rc
service xfinject_request /product/bin/xfinjectd -request /data/misc/rommgr/xfinject/request.json -allowlist /product/etc/xfinject/payloads.json
    class late_start
    user root
    group root shell
    disabled
    oneshot
    seclabel u:r:su:s0

service xfinject_autostart /product/bin/xfinjectd -request /data/misc/rommgr/xfinject-auto/request.json -allowlist /product/etc/xfinject/payloads.json
    class late_start
    user root
    group root shell
    disabled
    oneshot
    seclabel u:r:su:s0
```

## 八、踩坑记录

1. **xfinject 高级页不能伪装成 jnitrace 开关**  
   高级页是一次性 request 提交入口；持久 jnitrace 只能放在 `Trace` 分组开关里。

2. **framework 不应该直接加载 payload**  
   `system_server` 只负责写 request 和启动 service，payload 注入必须交给 xfinjectd。

3. **system_server 触发链路需要 sepolicy**  
   需要同时允许读取 `persist.rommgr.*` 和创建 `/data/misc/rommgr/...` request 文件，否则会出现 property / file avc denied。

4. **关闭开关必须无副作用**  
   `xfinject_jnilog=0` 时启动目标 App，不能出现 `xfinject_autostart`、`JniLog` 或新的 avc denied。

## 九、结论

本次功能达到预期：

- ROM 内置 xfinject release payload，不维护本地 fork 源码副本。
- ROMManager UI 语义清晰：`xfinject` 是高级手动页，`jnitrace:Arsylk/jnilog` 是持久开关。
- 不走 framework `System.loadLibrary("jnilog")`，而是在目标 App 启动前由 xfinject 等待并注入。
- demo App 和真实 App 均验证通过。
- 关闭开关时没有注入副作用。

## 十、后续维护规则

- 新 payload 接入时，先更新 allowlist / lock 文件和 hash，再做 UI 暴露。
- App 级持久能力统一走 `persist.rommgr.app.<pkg>.<feature>`。
- 任何自动注入类能力都要验证：开关关闭无副作用、开关打开能注入、验证后能清理开关。
- 若新增 ROMManager 页面或交互，必须先写设计草图并确认，不要直接改 UI 语义。
