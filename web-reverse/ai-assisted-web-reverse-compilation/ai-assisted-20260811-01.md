#  RSA 签名题的通用突破口：拿公钥 DER 前缀当内容锚

本文所有内容仅供学习交流使用，目标为公开的逆向练习靶站，不用于任何其他目的；不提供可直接批量采集的成品脚本，严禁用于商业及非法用途，否则后果与作者无关。


签名脚本 335KB，控制流平坦化，函数名全压缩成一两个字母。按名字钩函数，全落空。

你不知道该钩谁。

这种情况下有个通用解法：  ** 别用名字定位，用内容定位。  ** 而 RSA 题的内容锚是现成的，公钥的 DER
编码里有一段跟密钥无关的固定前缀，拿它整脚本 trace，命中的地方就是用公钥的地方，离明文拼装只有一步。

第一节讲这个锚怎么用，第二节起拿猿人学 match/27 的  ` token  ` 走一遍完整流程，顺带两个真会踩的坑：脚本里内嵌  ** 两个公钥
** 用错那个一律 403  ` token failed  ` ；PKCS  #1  v1.5 是  ** 随机填充  ** ，你算出来的 token
和抓包的永远不一样，这不代表你错了。


##  一、通用锚：公钥 DER 的 AlgorithmIdentifier

RSA 公钥的标准 DER 封装叫 SubjectPublicKeyInfo：


    SEQUENCE {
      SEQUENCE { OID 1.2.840.113549.1.1.1 (rsaEncryption), NULL }   ← 这段固定
      BIT STRING { SEQUENCE { modulus INTEGER, exponent INTEGER } }
    }

中间那个 AlgorithmIdentifier 跟密钥内容无关，只跟"这是个 RSA 公钥"有关。所以它在  ** 每一个  ** RSA
公钥里都一模一样。

用 openssl 实测三个位长，别信我，自己跑一遍：


    for b in 1024 2048 4096; do
      openssl genrsa -out /tmp/k.pem $b 2>/dev/null
      printf "RSA-%-5s " $b
      openssl rsa -in /tmp/k.pem -pubout -outform DER 2>/dev/null | xxd -p -l 26 | tr -d '\n'; echo
    done


    RSA-1024  30819f   300d06092a864886f70d0101010500  03818d0030818902
    RSA-2048  30820122 300d06092a864886f70d0101010500  0382010f003082
    RSA-4096  30820222 300d06092a864886f70d0101010500  0382020f003082
              ↑长度头   ↑与位长无关的不变段              ↑长度头

###  ★ 用中间那段，别用开头

我第一次做这题用的锚是  ` 30819f300d06092a  ` 。它能命中，但  ** 只对 1024 位有效  ** ，因为  ` 30819f
` 是 1024 位专属的 DER 长度头。换成 2048 位的站点就白搭。

** 通用锚是中间那 15 字节：  **


    300d06092a864886f70d0101010500

任意位长的 RSA 公钥都含这一段。存进你的常用锚清单，以后不管碰到 1024 还是 2048，一个锚通吃。

###  如果脚本存的是 base64

有些站点不存 hex，直接嵌 PEM 里那串 base64。这时候锚要换成 base64 形式，而且  ** base64
的分组对齐会因长度头字节数不同而错位  ** ：


    openssl rsa -in /tmp/k.pem -pubout | sed -n 2p | cut -c1-32


    RSA-1024   MIGfMA0GCSqGSIb3DQEBAQUAA4GNADCB    → 锚用  MA0GCSqGSIb3DQEBAQUAA
    RSA-2048   MIIBIjANBgkqhkiG9w0BAQEFAAOCAQ8A    → 锚用  ANBgkqhkiG9w0BAQEFAAOC
    RSA-4096   MIICIjANBgkqhkiG9w0BAQEFAAOCAg8A    → 锚用  ANBgkqhkiG9w0BAQEFAAOC

1024 位是一种相位，2048/4096 是另一种。搜的时候两个都试。

###  这招还能怎么用

同一个思路换个常量就能复用到别的算法族：

想找什么  |  拿什么当内容锚
---|---
RSA 公钥  |  ` 300d06092a864886f70d0101010500  `
标准哈希  |  SHA-256 的 IV  ` 6a09e667  ` 、SM3 的 T  ` 79cc4519  ` 、MD5 的 K 表首项  ` d76aa478  `
AES  |  S-box 首行  ` 637c777bf26b6fc5  `
base64  |  字母表  ` ABCDEFGHIJKLMNOPQRSTUVWXYZabcdef  `

** 函数名可以压缩，控制流可以平坦化，但常量改不了。  ** 常量是算法的身份证。


##  二、案例：猿人学 match/27 的 token

先给结论：


    token = base64( RSA_encrypt_PKCS1v15( 明文, 公钥key0 ) )
    明文  = "/api/question/27" + now + "27" + page      # 零分隔符拼接
    now   = GET /api/getTime                            # 唯一联网步

项  |  值
---|---
家族  |  RSA-1024，  ` e = 65537  `
填充  |  PKCS  #1  v1.5 type2，PS 为非零随机字节
变换  |  密文 128 字节 → 标准 base64
公钥  |  脚本内嵌 2 个 DER 公钥，均 1024/65537。  ** key0 有效，key1 诱饵  **
分派器  |  ` 27.js  ` 的 switch 型分派器  ` Gn  ` ，31 个 case
验证  |  live：key0 → 200 + 真实数据；key1 → 403  ` token failed  `

###  定性：base64 解出来是 128 字节

第一步永远是看 token 长什么样。


    import base64
    raw = base64.b64decode(抓包拿到的token)
    print(len(raw))               # 128

128 字节 = 1024 位。不是哈希（哈希是固定 16/20/32 字节），是  ** 块加密的输出  ** 。

再加一条判据：  ** 同一个页面刷两次，token 完全不同。  ** 哈希不会这样，要么输入里有时间戳，要么填充是随机的。这题两个都有。

` now  ` 从哪来，翻一下 XHR 记录：


    VMXHR url=…/api/getTime        stack: <send@s5> <ajax@s5> <$.ajax@s17> <t@s16> …
    VMXHR url=…/api/question/27?page=1&token=…

签名前先联一次网取服务端时间。这是新鲜度闸，也是  ** 唯一的联网依赖  ** ，其余全离线。


##  三、为什么按名钩会落空

` /match/27/js/27.js  ` ，335KB，控制流平坦化。先认形态：


    dispatch_type : switch          # 不是 table，不是线程栈机
    case_count    : 31
    dispatcher_fn : Gn
    handler_array : 无              # switch 分派，没有 handler 数组可枚举

两个问题叠在一起：

  1. ** switch 分派没有 handler 数组  ** 。table 型至少能把 handler 数组拉出来一个个看，switch 型全塞在一个大  ` switch  ` 里。
  2. ** 函数名全压缩  ** 成  ` Gn  ` 、  ` t  ` 、  ` c  ` 这种。

于是换第一节那个锚，整脚本 trace：


    capture --trace-source "30819f300d06092a" --trace-source-exec

一次命中。


##  四、一步抓到明文拼装

trace 命中后，明文构造点直接可读：


    inputs = [ '/api/question/27',  now,  '27',  page ]
    明文    =  '/api/question/27' + now + '27' + page

零分隔符，四段直接拼。填充走标准  ` pkcs1pad2  ` ，没魔改。

顺带一个发现：  ** RSA 是在脚本层做的，不在 VM 里。  ** 那 31 个 case 的 switch
分派器只负责把明文拼出来，加密本身调的是常规实现。

所以这题压根不用碰 VM。


##  五、两个公钥，第二个是诱饵

脚本里搜到  ** 两段长度 ≥200 的 hex  ** ，即两个内嵌 DER 公钥，都是 1024 位、  ` e=65537  ` 。

静态看不出哪个真。别猜，直接 e2e 试：


    for k in (0, 1):
        now = requests.get(BASE + "/api/getTime").text.strip()
        r = requests.get(BASE + "/api/question/27",
                         params={"page": 1, "token": token(now, 1, key=k)})
        print(k, r.status_code, r.text[:60])


    0 200 {"data":[...10 个整数...]}
    1 403 token failed

** key1 是诱饵钥  ** ，移植时固定  ` key=0  ` 。

这是 RSA 题的常见套路：内嵌多个公钥，只有一个是服务端私钥对应的那个。用错了不报错，就是 403，让你以为是明文拼错了。

判定方法很朴素，逐个发真实请求。静态分析在这里没有优势。


##  六、随机填充：别指望逐字节相等

这一节最容易让人误判"我失败了"。

PKCS  #1  v1.5 type2 的块结构：


    00 02 <PS: 非零随机字节，填满> 00 <msg>
    └─┬─┘ └────────┬────────┘   └┬┘ └─┬─┘
     头部      随机填充          分隔  明文

` PS  ` 是随机的（站点用  ` Math.random  ` 取字符）。所以  ** 同一个明文，每次加密出来的密文都不同  ** 。

结构自检，两次调用应该不相等：


    python3 -c "from q27_token import token; print(token(1,1) != token(1,1))"
    # True   ← 相等反而说明你的填充写死了

直接后果：  ** 你没法把离线算的 token 和抓包的 token 逐字节比对。  **

上一题（match/26）是魔改 SM3，确定性哈希，2 个样本逐字节一致就能收工。这题不行。

正确性只能靠  ** 真实请求的 200/403  ** 来判。所以第五节那个 e2e 循环不是锦上添花，它是这题唯一的验收标准。


##  七、完整复现代码


    #!/usr/bin/env python3
    """猿人学 match/27 token
    明文 = "/api/question/27" + now + "27" + page     # 注意比 match/28 少一个 '$'
    填充 = PKCS#1 v1.5 type2，PS 随机非零 → 同明文每次密文不同
    """
    import base64, json, os, pathlib, sys

    KEYS = json.loads((pathlib.Path(__file__).parent / "keys.json").read_text())

    def token(now: int, page: int = 1, key: int = 0, qid: str = "27") -> str:
        n, e = int(KEYS[key]["n"]), KEYS[key]["e"]
        msg = f"/api/question/{qid}{now}{qid}{page}".encode()
        k = 128                                    # 1024 位 = 128 字节
        ps = bytearray()
        while len(ps) < k - 3 - len(msg):          # PS 必须全为非零字节
            ps += bytes(b for b in os.urandom(32) if b)
        block = b"\x00\x02" + bytes(ps[: k - 3 - len(msg)]) + b"\x00" + msg
        c = pow(int.from_bytes(block, "big"), e, n)
        return base64.b64encode(c.to_bytes(k, "big")).decode()

    if __name__ == "__main__":
        now  = int(sys.argv[1])
        page = int(sys.argv[2]) if len(sys.argv) > 2 else 1
        key  = int(sys.argv[3]) if len(sys.argv) > 3 else 0
        print(token(now, page, key))

` keys.json  ` 就两个对象，模数从脚本里抠出来：


    [
      {"n": "9111028991277797…927289",  "e": 65537},
      {"n": "10680973798858985…772121", "e": 65537}
    ]

整个加密只有一行  ` pow(m, e, n)  ` ，不需要任何密码学库。RSA 公钥运算就是一次模幂。

端到端：


    now = requests.get(BASE + "/api/getTime").text.strip()
    tk  = token(int(now), page=1, key=0)
    r   = requests.get(BASE + "/api/question/27", params={"page": 1, "token": tk})
    assert r.status_code == 200 and r.json()["data"]     # 200 + 10 个整数


##  八、同族题横向复用

这套结构不止一题在用：

题  |  明文
---|---
match/27  |  ` path + now + qid + page  `
match/28  |  ` path + $ + now + qid + page  `

** 差一个  ` $  ` 分隔符。  **

逆完一题，同族的只需要核对分隔符和题号，剩下照抄。遇到 RSA 题先别急着深挖，翻翻自己以前的笔记有没有同族的。


##  九、三条带走

  1. ** 常量是算法的身份证。  ** 函数名可以压缩，控制流可以平坦化，但常量改不了。名字不可靠的时候，用内容锚定位比用名字定位可靠得多。RSA 的通用锚是  ` 300d06092a864886f70d0101010500  ` 。
  2. ** RSA 题先数公钥有几个。  ** 多个公钥只有一个真是常见套路，用错的那个返回 403 而不是报错。逐个 e2e 试，别静态猜。
  3. ** 看清填充是不是随机的，再决定验收标准。  ** 确定性填充或哈希可以逐字节比对；PKCS  #1  v1.5 这种随机填充只能靠真实请求的 200/403。搞错这一点，你会把已经做对的方案当成失败丢掉。
