##  rs-while的构造器

原字节码while的大概识别特征：


    [loopStart]  条件计算指令...             JUMP_IF_FALSE  → [exit]    ← 锚点① 有出口跳转
                 循环体指令...
                 JUMP  → [loopStart]        ← 锚点② 无条件回跳，且目标 < 当前地址
    [exit]       ...                        ← 锚点③ exit 就是 JUMP_IF_FALSE 的目标

##  第一步：定义变量字典

在真实的混淆代码中，变量名往往是随机生成的（比如  ` _$gX  ` ），并且每次刷新都在变。为了方便阅读，我们提取出一个变量映射表  ` N  `
（函数名临时固定）：

##  第三步：编写代码生成引擎

这是整个生成器的核心。它遍历  ` BYTECODE  ` 数组，遇到不同的数字，就向  ` out  ` 数组中推入相应的代码字符串。

我们在这里不仅生成了外层的  ` while  ` 循环，还在循环内部分支出了一个  ** 微型栈式解释器  ** （包含：读取数据、加法运算、结束返回）：


    function generate(pos, out) {    let pc = pos;    while (true) {        const op = BYTECODE[pc++];        switch (op) {            case 1:  out.push("(function(");                          break;            case 2:  out.push(N.code, ",", N.data, "){");             break;
                // 声明变量并初始化模拟栈 stack=[]            case 3:  out.push("var ", N.pc, "=0,", N.res, ",", N.op, ",stack=[];"); break;            case 4:  out.push("while(1){");                           break;
                // 核心取指操作：op = code[pc++]            case 5:  out.push(N.op, "=", N.code, "[", N.pc, "++];");  break;

                // 分支 1：操作码 1 (压栈指令：从 data 中取值压入 stack)            case 6:  out.push("if(", N.op, "===1){");                 break;            case 7:  out.push("stack.push(", N.data, ".shift());");   break;
                // 分支 2：操作码 2 (ADD指令：弹出两个数字相加，重新压栈)            case 8:  out.push("}else if(", N.op, "===2){");           break;            case 9:  out.push("stack.push(stack.pop()+stack.pop());");break;
                // 分支 3：操作码 0 (Halt指令：结束运行并提取最终结果)            case 10: out.push("}else if(", N.op, "===0){");           break;            case 11: out.push(N.res, "=stack.pop();break;");          break;


                // BYTECODE 中连续调用了两次 case 12：            // 第一次用于闭合 else if(op===0){ 块            // 第二次用于闭合 while(1){ 循环，防止 SyntaxError 报错！            case 12: out.push("}");                                   break;

###  3\. Eval 动态执行

最终，生成的这段代码本身就是一个完整的自执行函数。
它传入了机器码  ` [1, 1, 2, 0]  ` 和数据  ` [10, 20]  ` ，这等价于：

  1. ` op=1  ` : 将  ` 10  ` 压入栈。
  2. ` op=1  ` : 将  ` 20  ` 压入栈。
  3. ` op=2  ` : 弹出  ` 20  ` 和  ` 10  ` ，相加得到  ` 30  ` ，将  ` 30  ` 压入栈。
  4. ` op=0  ` : 弹出  ` 30  ` 赋值给  ` result  ` 并结束运行。


    console.log("\n=== eval 执行结果 ===");const evalResult = eval(generatedCode);  console.log("返回值:", evalResult);  // 完美输出: 30

##  “业务逻辑的 while 循环”和“虚拟机自身的 while 循环（执行引擎）”的区别

###  1\. 常规 VMP：静态引擎 + 隐式跳转（ push/pop 修改 PC）

在常规的 VMP（比如 Jscrambler、OLLVM、各种控制流平坦化）中，架构是这样的：

  * ** 执行引擎（解释器）是静态写死在 JS 里的  ** 。逆向者一打开代码，就能看到一个巨大的  ` while(1) { switch(op) { ... } }  ` 壳子。（见文末）
  * **业务层面的循环怎么实现？**没有任何明文的  ` while  ` 字符串。如果你原来的代码里有一个  ` while (a < 10)  ` ，VMP 会把它编译成类似汇编的指令：
    1. 把  ` a  ` 和  ` 10  ` 压栈 (  ` push  ` )
    2. 比较大小 (  ` cmp  ` )
    3. 如果不符合条件，  ** 修改 PC 指针跳出  ** (  ` pop  ` 然后  ` pc = 99  ` )
    4. 如果符合条件，执行代码，最后  ** 修改 PC 指针往回跳  ** (  ` pc = 1  ` )。


###  2\. 当前网站 VMP：双层嵌套 + 动态组装引擎

现在看到的这段代码，  ** 它本身并不是用来执行业务逻辑的虚拟机，而是“用来制造虚拟机的机器”！  **

while 采用的是**“双层 VMP 架构”**：

  * ** 第一层：组装机（Builder）  ** 。也就是我们刚才拆解的代码，它通过读取一个数组  ` [49, 14, 30, ...]  ` ，把  ` "while(1){"  ` 、  ` "op="  ` 、  ` "code["  ` 这些字符串碎片，拼成一段完整的 JS 虚拟机代码。
  * ** 第二层：真正的 VMP 引擎（Engine）  ** 。组装机拼好字符串后，调用  ` eval()  ` 或者  ` new Function()  ` ，在内存中“凭空”创造出一个虚拟机引擎。
  * 这个内存里的引擎，再去执行业务代码的 push/pop/修改 PC 操作。


###  3\. 为什么rs会有明文的  ` "while(1){"  ` 字符串？

因为  ** 原生的 JS 必须依靠  **` while  ` ** 来保持引擎的持续运转  ** 。

  * ** 常规 VMP  ** 是直接把引擎写在硬盘/文件里：


    // 常规混淆直接暴露引擎外壳var pc=0; while(1){    var op=code[pc++];    if(op==1) push();    if(op==2) pc=10; // 模拟循环}

  * ** 瑞数 VMP  ** 把引擎外壳变成了字符串数组，动态拼合：


    // 瑞数通过这种方式，让你在静态代码里搜不到 while(1) 和 switchout.push("while", "(", "1", ")", "{");out.push( N.op, "=", N.code, "[", N.pc, "++]");// ...最后 eval(out.join(''))

###  4\. 这个vmp“变简单”了吗？

** 绝对不是，这反而极大增加了静态分析的难度。  **

  1. ** 静态分析彻底失效  ** ：在瑞数的混淆脚本里，你根本搜不到完整的  ` while(1) { switch(){...} }  ` 。因为  ** 真正的执行代码根本就不在 AST 树里，而在运行时的字符串里  ** 。

  2. ** 调试极其痛苦  ** ：因为真正的虚拟机代码是在  ` eval  ` 虚拟机环境中运行的（也就是 Chrome devtools 里的  ` VM1234  ` 这种虚拟文件）。你无法在页面加载前给它打上断点，必须先追踪到  ` eval  ` 的入口，把生成的代码扣出来，再去分析真实的指令。
