##  Node.js 浏览器环境模拟：从 Addon 再到纯 Node

经过多日的探索，完成了addon用来做追踪的框架。原理是把之前js层做的初始化对象全部先在c层初始化（原型链和方法保护）完成，然后导入到sanbox作为全局。使用的时候
jsdom只作为实际执行者，不使用它的任何原型链。这样的优点是将创建初始化的过程都压缩在c层，用户只要写一些缺失的env就可以了，极大的减少了用户代码。但是同时也发现了一些局限性。

##  核心问题：V8 Context 隔离导致的问题

###  问题表现


    // 在 VM Context 中执行const spans = document.getElementsByTagName('span');
    console.log(spans instanceof HTMLCollection);  // ❌ false（应该是 true）console.log(spans[0] instanceof HTMLSpanElement);  // ❌ falseconsole.log(HTMLSpanElement.prototype === spans[0].__proto__);  // ❌ false

** 问题根源  ** ：  ` instanceof  ` 失败，原型链断裂。

###  深层原因分析

####  V8 Context 的本质

V8 的 Context 是一个  ** 完全隔离的 JavaScript 执行环境  ** ，每个 Context 都有：


    Context A                          Context B├─ Object (构造函数)                ├─ Object (构造函数)├─ Array (构造函数)                 ├─ Array (构造函数)├─ Function (构造函数)              ├─ Function (构造函数)├─ HTMLElement (我们创建的)         ├─ HTMLElement (我们创建的)└─ HTMLSpanElement (我们创建的)     └─ HTMLSpanElement (我们创建的)

** 关键点  ** ：即使名字相同，两个 Context 中的构造函数是  ** 不同的对象  ** ！


    // 在主 Context 创建构造函数Local<FunctionTemplate> tpl = FunctionTemplate::New(isolate);Local<Function> ctor_main = tpl->GetFunction(mainContext).ToLocalChecked();
    // 在 VM Context 创建构造函数Local<Function> ctor_vm = tpl->GetFunction(vmContext).ToLocalChecked();
    // ctor_main != ctor_vm  (不同的对象！)
