## 正文

从addon转为魔改的node使用。更改的原因是vm调试的问题，使用原生vm会污染自己构造的context，使用自己的context会直接运行无法进入断点，于是将源码移植到node中并进行了重构。源码及node.exe已放星球，正在更新中。


##  核心方案：内部绑定而非 .node 插件

更新后KhBox 的 C++ 核心不是通过  ` node-gyp  ` 编译的普通  ` .node  ` addon，而是直接编译进了自定义
Node.js 二进制内部（  ` NODE_BINDING_CONTEXT_AWARE_INTERNAL  ` ）。

加载方式从：


    // 旧方式：外部 addon 文件const addon = require('./tools/khbox_addon.node');

变为：


    // 新方式：内部绑定，开箱即用const addon = globalThis.khBox;

这样做的好处：无需  ` .node  ` 文件分发，无 ABI 兼容问题，启动更快。


##  重构前的问题

重构前只有一个文件  ` khbox_pre.js  ` ，700 多行，职责完全混在一起：

  * addon 加载
  * 全局状态（  ` KH_STATE  ` ）
  * C++ 回调函数（  ` jsDispatch  ` ）
  * 工具函数（  ` safeDesc  ` 、  ` customConsole  ` ）
  * 框架主类（  ` KhEnv  ` ）

同时  ` tools/khbox_bootstrap.js  ` 命名模糊，看不出它实际上是  ** 在 V8 browserContext 内部运行
** 的初始化脚本，和普通工具文件混在一起。

##  各文件职责详解

###  ` tools/dispatch.js  ` — 引擎层

这是整个框架的"发动机"，不对外暴露任何业务逻辑。

** 职责：  **

  * ` const addon = globalThis.khBox  ` — 获取 C++ 内部绑定，并做 null 检查
  * ` KH_STATE  ` — 全局状态单例（配置、envFuncs、日志）
  * ` safeDesc  ` /  ` customConsole  ` — 日志工具，把任意 JS 值格式化为可读字符串
  * ` findProtoOwner  ` — 沿原型链向上查找属性归属类（处理继承关系）
  * ` unwrapArguments  ` — 把 Shadow 对象解包为 JSDOM impl 对象
  * ` jsDispatch  ` —  ** C++ 拦截后的 JS 回调核心  **

` jsDispatch  ` 是整个框架最关键的函数。每当 browserContext 里的 JS 访问任何 DOM 属性或方法，C++
层都会拦截并调用这个函数。它的调度逻辑：


    属性访问 → C++ 拦截 → jsDispatch(name, receiver, holder, args)    │    ├─ 优先走 envFuncs Hook（用户自定义实现）    │    └─ 否则 unwrap(holder) 拿到 JSDOM impl，直接代理操作           ├─ get:       impl[prop]           ├─ set:       impl[prop] = value           ├─ method:    impl[prop].apply(impl, args)           └─ enumerate: Object.getOwnPropertyNames(impl)

###  ` tools/KhEnv.js  ` — 框架层

这是使用者直接打交道的类。  ` main.js  ` 、  ` server.js  ` 都  ` require('./tools/KhEnv')  `
。

** 核心方法：  **

####  ` init()  `

加载  ` ecma_standard.json  ` （842 个 DOM 类定义），过滤掉 V8 已有的内置类（Error、Array 等），然后调用：


    addon.initialize(filteredConfig);   // 把 DOM 类模板注册进 V8addon.initDispatcher(jsDispatch);   // 设置 C++ → JS 的回调函数

这步只需执行一次，server.js 在全局启动时调用，后续每个请求复用模板。

####  ` createDocument(html, url, userVar)  `

完整的浏览器环境创建流程：


    1. new JSDOM(html, { url })         ← 真实 DOM 实现（数据层）2. addon.createBrowserContext()     ← 创建 V8 Context（window.constructor.name === 'Window'）3. 注入 setTimeout / console 等     ← Node 侧函数桥接到 browser context4. addon.runScript(ctx, CTX_INIT_CODE)  ← 在 VM 内运行 ctx_init.js5. 初始化 Plugin / MimeType shadow   ← 绕过 illegal constructor 创建实例

返回  ` { contextvm, jsdom, shadowRefs, userVar }  ` 。

####  ` loadEnvFuncs(path, jsdom, shadowRefs, userVar)  `

动态加载  ` envFuncs.js  ` ，将 DOM Hook 函数注册到  ` KH_STATE.envFuncs  ` 。每次调用都会清除缓存重新
require，方便热更新。

####  ` executeScript(code, context)  `

通过 Node  ` inspector  ` 启用调试域后，调用  ` addon.runScript(contextvm, code,
'input.js')  ` 在 browserContext 里执行目标 JS。

####  ` smartWait(maxTimeout, interval)  `

等待所有  ` setTimeout  ` 执行完毕（通过  ` asyncState.counter  ` 计数），最大超时 30 秒。


###  ` tools/ctx_init.js  ` — VM 内部初始化

** 这个文件的特殊之处：它不在 Node 环境里运行，而是被  **` addon.runScript  ` ** 注入到 browserContext
里执行。  **

它完成的工作：


    // 1. 把 JSDOM window 对象绑定到 C++ shadow 的 globalThis 上addon.setImpl(globalThis, __jsdomWindow);
    // 2. 为每个子对象创建 shadow 实例并绑定 JSDOM implconst shadow = addon.createInstance(globalThis, 'HTMLDocument');addon.setImpl(shadow, jsdomWindow.document);shadowRefs['document'] = shadow;
    // 3. 同理处理 navigator / location / history / screen / performance

这样，当目标 JS 访问  ` document.cookie  ` 时，C++ 拦截后通过  `
addon.unwrap(shadow_document)  ` 拿到 JSDOM document，再代理到真实实现。

旧名  ` khbox_bootstrap.js  ` 不能体现"在 VM 内运行"这个关键属性，改名为  ` ctx_init.js  `
（context initialization）更准确。


###  ` tools/envFuncs.js  ` — DOM Hook 实现

这是补环境的"业务层"——定义所有需要特殊处理的 DOM 属性和方法。


    module.exports = function(KH_STATE, jsdom, shadowRefs, userVar) {    const addon = KH_STATE.addon;    return {        // Window 子对象 getter → 返回对应 shadow 实例        "Window_document_get":  () => shadowRefs.document,        "Window_navigator_get": () => shadowRefs.navigator,
            // Navigator 属性 → 从 userVar 读取真实浏览器数据        "Navigator_userAgent_get": function() { return userVar.navigator.userAgent; },        "Navigator_webdriver_get": function() { return false; },
            // document.all → 返回特殊的 HTMLAllCollection（能通过 typeof === 'undefined' 检测）        "Document_all_get": function() { ... },
            // Error.prepareStackTrace → 过滤掉 khbox 自身的调用帧        "Error_prepareStackTrace": function(error, callSites) { ... },        // ...共 55 个 Hook    };};


###  ` server.js  ` — HTTP 签名服务

将整个框架封装为 HTTP API，供 Python 等爬虫调用：


    POST /sign          单次签名POST /sign/batch    批量签名（顺序执行，避免状态竞争）GET  /health        健康检查GET  /pages         列出可用页面配置

** 设计决策：  **

  * ** 全局  **` init()  ` ** 一次  ** ：  ` addon.initialize()  ` （注册 842 个 DOM 模板）在服务启动时执行一次，每个请求无需重复初始化，大幅降低延迟。
  * ** 每次请求独立 JSDOM + browserContext  ** ：完全隔离，不共享 cookie / localStorage / DOM 状态。
  * ** batch 顺序执行  ** ：V8 脚本执行是 CPU 密集型，  ` KH_STATE.envFuncs  ` 是进程级共享状态，并发请求会导致 Hook 互相覆盖。顺序执行兼顾隔离与正确性。

** 请求体示例（使用预置页面）：  **


    POST /sign{    "pageName":  "rs",    "url":       "https://www.example.com/",    "cookies":   "session=abc123",    "userAgent": "Mozilla/5.0 ...",    "timeout":   30000,    "execAsync": true}

** 请求体示例（自定义脚本）：  **


    POST /sign{    "url":        "https://www.example.com/api",    "scriptCode": "document.cookie = 'token=' + btoa(navigator.userAgent);",    "execAsync":  false}

** 响应：  **


    {    "success": true,    "data": {        "cookie":        "token=TW96aWxsYS81...",        "localStorage":  {},        "sessionStorage": {}    },    "meta": {        "executionTime": 637,        "pageName":      "custom"    }}


###  ` spider.py  ` — Python 客户端

封装了对签名服务的调用，管理 Cookie 同步，提供三种使用模式：


    client = KhBoxClient("http://127.0.0.1:3000")
    # 模式 1：使用预置页面配置result = client.sign(url="https://target.com/", page_name="rs")
    # 模式 2：传入自定义 JSresult = client.sign(url="https://target.com/", script_code=js_code)
    # 模式 3：传入完整 HTML + JSresult = client.sign(url="https://target.com/", script_code=js_code, html=html_str)
    # 模式 4：批量results = client.sign_batch([task1, task2, task3])

签名成功后，Cookie 会自动同步回  ` requests.Session  ` ，后续请求直接携带签名凭证。


##  完整数据流


    [Python spider.py]    POST /sign { url, cookies, scriptCode }        ↓[server.js]    new KhEnv().init()           ← 复用全局模板，无需重新初始化    .createDocument(html, url)   ← 创建隔离的 JSDOM + browserContext    .loadEnvFuncs(...)           ← 注册 55 个 DOM Hook    .executeScript(code)         ← 在 browserContext 里跑目标 JS    .smartWait()                 ← 等 setTimeout 跑完    extractResult(context)       ← 提取 cookie / localStorage / customResult        ↓[jsDispatch in dispatch.js]      ← 目标 JS 访问 DOM 时 C++ 回调    envFuncs Hook → 返回自定义值    or addon.unwrap(shadow) → JSDOM impl 代理        ↓[ctx_init.js（运行在 VM 内）]    ← shadow ↔ JSDOM 绑定关系在此建立        ↓[C++ globalThis.khBox]    createBrowserContext()       ← 真正的 Window V8 Context    runScript()                  ← 在 Context 里执行 JS    createInstance()             ← 绕过 illegal constructor    setImpl() / unwrap()         ← shadow ↔ impl 双向绑定


##  关键反检测特性

检测点  |  处理方式
---|---
` window.constructor.name  ` |  C++  ` createBrowserContext()  ` 用 Window FunctionTemplate 创建 Context，天然为  ` "Window"  `
` instanceof HTMLDivElement  ` |  C++ 模板继承链完整，  ` div instanceof HTMLDivElement/HTMLElement/Element/Node/EventTarget  ` 全部通过
` Function.toString()  ` native  |  ` addon.safeFunc(fn, name)  ` 让函数 toString 返回  ` [native code]  `
` document.all  ` 双重性  |  ` typeof document.all === 'undefined'  ` 但  ` document.all[0]  ` 可访问，C++  ` HTMLAllCollection  ` 实现
` navigator.webdriver  ` |  envFuncs Hook 强制返回  ` false  `
` Error.stack  ` 堆栈  |  ` prepareStackTrace  ` Hook 过滤掉 khbox 自身调用帧
` Object.prototype.toString.call(window)  ` |  C++ 设置  ` Symbol.toStringTag = 'Window'  ` ，返回  ` [object Window]  `


##  异步 Token 获取 Demo

###  场景

真实的反爬 JS 往往不会同步返回签名结果，而是通过  ` setTimeout  ` 或 Promise 异步计算后写入 cookie /
全局变量。KhBox 对这类场景的处理分两步：

  1. ` smartWait  ` 在脚本执行后自动等待所有  ` setTimeout  ` 跑完（通过  ` asyncState.counter  ` 计数）
  2. ` window.__khResult  ` 约定：脚本把任意结果写到这个全局变量，  ` extractResult  ` 通过  ` addon.runScript  ` 从 V8 context 读回 Node 侧

###  Demo 代码（  ` pages/demo_async/input.js  ` ）


    // 模拟耗时 2s 的异步签名function fetchToken(url, cookie) {    return new Promise(function(resolve) {        setTimeout(function() {            var raw   = url + '|' + cookie + '|' + Date.now();            var token = btoa(raw).replace(/=/g, '').slice(0, 32);            resolve(token);        }, 2000);    });}
    (function() {    var url    = location.href;    var cookie = document.cookie || 'session=demo123';
        fetchToken(url, cookie).then(function(token) {        // 写入 cookie（走 jsDispatch → JSDOM 代理）        document.cookie = 'kh_token=' + token;
            // 写入 __khResult（存在 V8 context globalThis 上，供 extractResult 读取）        window.__khResult = { token: token, url: url, timestamp: Date.now() };    });})();

###  ` extractResult  ` 读取原理

` document.cookie  ` 和  ` localStorage  ` 的写入由 jsDispatch 代理到 JSDOM，所以从  `
jsdom.window  ` 直接读。
而  ` window.__khResult  ` 是直接写在 V8 context 的 globalThis 上，JSDOM 没有副本，必须用  `
addon.runScript  ` 回到 V8 侧读取：


    function extractResult(context) {    const { jsdom, contextvm } = context;    // ...读 cookie / localStorage（从 jsdom）...
        // 从 V8 browserContext 读取 __khResult    const khResult = addon.runScript(contextvm, 'globalThis.__khResult', '__khResult_read.js');    if (khResult != null) result.customResult = khResult;}
