##  一、Canvas 指纹检测原理

Canvas 指纹是风控系统判断是否为真实浏览器的重要手段。网站在  ` <canvas> `
上绘制相同内容，读取像素数据，不同的操作系统、GPU、字体引擎会产生细微差异，从而形成"指纹"。

但在 Node.js 模拟环境下，这些差异会以特征形式暴露出来，被风控系统识别。

当前框架还是用 jsdom带的canvas node库，进行基本的函数，但是对函数进行了保护。如果是固定值，则进行了hook或者使用配置文件的值。


##  二、风控检测了什么（  ` jsdom_canvas.js  ` 分析）

检测脚本  ` test_jsdom/jsdom_canvas.js  ` 实现了一套综合评分系统（满分 100），包含以下五个维度：

###  检测项一：  ` fillText  ` 原生代码检测（-30分）


    if (!ctx.fillText.toString().includes('[native code]')) {    report.score -= 30;    report.flags.push('fillText_hooked');}

检测  ` fillText  ` 是否被 Hook 篡改。被 Hook 的方法  ` toString()  ` 返回的是函数源码，而非  `
function fillText() { [native code] }  ` 。

###  检测项二：  ` toDataURL  ` 基本可用性（-50分）


    const dataURL = canvas.toDataURL('image/png');if (!dataURL.startsWith('data:image/png')) {    report.score -= 50;    report.flags.push('toDataURL_failed');}

最基础的检测：canvas 必须能返回合法的 PNG data URL。

###  检测项三：PNG Chunk 结构分析（-20分）


    const chunks = parsePngChunks(dataURL);// 期望结构：IHDR → sRGB → IDAT → IEND
    if (!chunks.includes('sRGB')) {    report.score -= 20;    report.flags.push('missing_sRGB_chunk');}if (chunks.includes('pHYs')) {    report.score -= 20;    report.flags.push('has_pHYs_chunk');}

这是  ** 二进制级别  ** 的检测。  ` parsePngChunks  ` 直接解析 PNG 字节流的 chunk 列表：

Chunk  |  含义  |  浏览器行为  |  Cairo (node-canvas) 行为
---|---|---|---
` sRGB  ` |  色彩空间声明  |  ✅ 存在  |  ❌ 缺失
` pHYs  ` |  物理像素尺寸  |  ✅ 不存在  |  ⚠️ 存在（暴露特征）

最小 PNG 占位图（如常见的 1x1 透明 PNG）只有  ` IHDR → IDAT → IEND  ` ，  ** 缺少 sRGB chunk  **
，直接触发  ` missing_sRGB_chunk  ` 扣分。

###  检测项四：WebP 格式支持（-30分）


    const webpURL = canvas.toDataURL('image/webp');report.webpSupported = webpURL.startsWith('data:image/webp');if (!report.webpSupported) {    report.flags.push('webp_unsupported');}

真实 Chrome 浏览器支持 WebP 编码，  ` toDataURL('image/webp')  ` 返回  `
data:image/webp;base64,...  ` 。
Node.js 的  ` node-canvas  ` / jsdom 默认不支持 WebP，会 fallback 到 PNG，立即暴露。


##  三、框架如何对抗：  ` envFuncs.js  ` 实现

KhBox 框架通过 Hook 机制拦截 V8 层的 DOM 属性访问，  ` envFuncs.js  ` 是所有 Hook
实现的注册入口，以工厂函数形式导出，接收当前 session 的  ` userVar  ` 配置。

###  3.1 WebP 支持伪造


    "HTMLCanvasElement_toDataURL": function(type, ...args) {    const mimeType = (typeof type === 'string' && type) ? type : 'image/png';
        // WebP 单独处理，直接返回合法的 WebP data URL    if (mimeType === 'image/webp') {        return 'data:image/webp;base64,UklGRlYAAABXRUJQVlA4...';    }    // ...}

无论是否开启随机模式，  ` image/webp  ` 类型请求统一返回一个真实的 WebP 格式 data URL（以  `
data:image/webp  ` 开头），通过检测项五。

###  3.2 PNG Chunk 结构修复（随机模式核心）

最小占位 PNG 缺少  ` sRGB  ` chunk，无法通过检测项四。框架在随机模式下用 Node.js 内置模块  ** 从字节级别手动构建  **
一个结构正确的 PNG：

** PNG 结构要求：  **


    [PNG魔数] → IHDR chunk → sRGB chunk → IDAT chunk → IEND chunk

** 实现步骤：  **


    ① 构建 CRC32 查找表（256项，PNG规范要求每个chunk附带CRC32校验）② _pngChunk(type, data) → 按 PNG 规范组装：[4字节长度][4字节类型][data][4字节CRC32]③ _generateRandomPng()：   - IHDR：1×1像素，8-bit RGB (colorType=2)   - sRGB：1字节，Rendering Intent = 0（Perceptual）← 关键，解决 missing_sRGB_chunk   - IDAT：filter_byte(0x00) + [R, G, B] 像素数据，zlib.deflateSync 压缩   - IEND：空chunk   - 最终 base64 编码为 data URL

** 随机像素生成：  **


    const rand5 = () => Math.floor(Math.random() * 11) - 5;const r = Math.max(0, Math.min(255, 210 + rand5()));  // 205~215const g = Math.max(0, Math.min(255, 200 + rand5()));  // 195~205const b = Math.max(0, Math.min(255, 195 + rand5()));  // 190~200

每次 session 在基准色上施加 ±5 的随机偏移，模拟不同 GPU/驱动渲染的细微差异。

###  3.3 Session 级别缓存


    // 工厂函数作用域内只生成一次const _sessionPng = isCanvasRandom ? _generateRandomPng() : null;

关键设计：  ** 同一个 session 内所有  **` toDataURL()  ` ** 调用返回同一个值  ** 。

这符合真实浏览器的行为——在相同的机器和浏览器上，同样的绘制内容每次读出来的像素是一致的。如果每次调用都返回不同值，反而会被检测到"不稳定"。

###  3.4 完整  ` toDataURL  ` 分支逻辑


    toDataURL(type) 调用    │    ├─ type == 'image/webp'    │       └─ 返回固定 WebP data URL（始终通过WebP检测）    │    ├─ isCanvasRandom == true    │       └─ 返回 _sessionPng（session启动时生成的随机PNG，含sRGB chunk）    │    ├─ canvasData.dataURL 存在（userVar 配置了固定值）    │       └─ 返回配置值（替换MIME前缀匹配type参数）    │    └─ 兜底占位图（image/jpeg 或 image/png 最小占位）


##  四、框架改造了哪些地方

本次为支持 canvas 随机指纹，共修改三个文件：

###  4.1  ` tools/KhEnv.js  ` — 全局配置

在  ` KHENV_CONFIG  ` 中增加一个开关：


    const KHENV_CONFIG = {    // ... 其他配置    canvasRandom: false,  // 新增：canvas 随机指纹全局默认值};

这是最低优先级的兜底默认值，不改配置文件就默认关闭随机。

###  4.2  ` server.js  ` — 请求参数透传

** 改动一：  ** ` runSign()  ` 解构增加  ` canvasRandom  ` 字段：


    const {    pageName, scriptCode, html, url,    cookies, userAgent, timeout, execAsync,    canvasRandom,   // 新增，从 POST body 接收} = params;

** 改动二：  ** ` mergeRequestData()  ` 签名和函数体：


    function mergeRequestData(userVar, { url, cookies, userAgent, canvasRandom }) {    // ...    // 请求body优先级最高，undefined 时不覆盖（保留 userVar.js 的配置）    if (canvasRandom !== undefined) uv.canvasRandom = !!canvasRandom;    return uv;}

** 改动三：  ** 调用处透传：


    userVar = mergeRequestData(userVar, { url, cookies, userAgent, canvasRandom });

###  4.3  ` tools/envFuncs.js  ` — 核心实现

工厂函数内部新增：

  1. ** 优先级读取  ** ：  ` userVar?.canvasRandom ?? khBox.config?.canvasRandom ?? false  `
  2. ** CRC32 实现  ** ：纯 JS 查找表，无外部依赖
  3. ** PNG Chunk 构建器  ** ：  ` _pngChunk(type, data)  ` 按 PNG 规范组装每个 chunk
  4. ** 随机 PNG 生成器  ** ：  ` _generateRandomPng()  ` ，使用 Node.js 内置  ` zlib  ` 压缩
  5. ** Session 缓存  ** ：  ` _sessionPng  ` 在工厂函数作用域内只计算一次
  6. ` toDataURL  ` ** 分支逻辑**：WebP → 随机模式 → 固定配置 → 兜底


##  五、优先级与使用方式

三层配置，优先级从高到低：


    POST /sign { canvasRandom: true }        ← 最高：调用方按请求控制    pages/xxx/userVar.js canvasRandom    ← 中：页面级别固定配置        KHENV_CONFIG.canvasRandom        ← 最低：全局默认（false）

** 调用示例：  **


    # 开启随机（每个session返回略有差异的PNG，含正确sRGB chunk）curl -X POST http://localhost:3001/sign \  -H 'Content-Type: application/json' \  -d '{"pageName":"demo","canvasRandom":true}'
    # 关闭随机（走 userVar 固定配置或占位图）curl -X POST http://localhost:3001/sign \  -H 'Content-Type: application/json' \  -d '{"pageName":"demo","canvasRandom":false}'

##  七、局限性与后续方向

  1. ** 颜色数量检测  ** ：随机 PNG 只有 1 个像素、1 种颜色，颜色数量检测仍无法通过。这需要结合具体页面的  ` getImageData  ` Hook 来处理，或返回带复杂内容的 canvas 图像。
  2. ` fillText  ` ** 原生检测**：框架通过  ` addon.safeFunc()  ` 让 Hook 函数的  ` toString()  ` 返回  ` [native code]  ` ，这部分在 V8 层面已处理，不在本次改造范围内。
  3. ** WebGL 指纹  ** ：Canvas 2D 指纹之外，WebGL 指纹（renderer、vendor、精度等）是另一个检测维度，  ` userVar.customData.webgl  ` 已有配置入口，后续可独立展开。
