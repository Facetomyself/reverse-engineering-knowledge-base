## 正文

khbox经过反复选择addon模式和魔改node，最终还是选择了后者。

这篇文章说一下怎么把khbox代码放在在node源码中。完整源码和详细文档在知识星球。  整个魔改方案的改动量非常小，核心只有四处。


##  改动只涉及四个文件

###  1\.  ` node.gyp  ` — 把 khBox 的源文件纳入编译

这是 Node.js 的构建配置文件。要让 khBox 的 C++ 代码参与编译，只需要在  ` node_sources  ` 列表里声明它的所有  `
.cc  ` 和  ` .h  ` 文件。找到  ` src/node_i18n.cc  ` 这一行，在它后面插入 khBox 的文件列表，就这一处改动。


    'src/node_i18n.cc',
    'src/khbox/khbox_binding.cc','src/khbox/khbox_shadow_wrapper.cc','src/khbox/khbox_template_factory.cc','src/khbox/khbox_dispatcher.cc',// ... 其余文件

###  2\.  ` src/node_binding.cc  ` — 注册 khBox 为内置模块

这里是 Node.js 所有内置 binding 的注册中心。需要改三处：

** 顶部加 include：  **


    #include "util.h"#include "khbox/khbox_binding.h"  // 新增

** 在宏列表里注册模块名：  **


    ounter(lineounter(lineounter(lineV(js_udp_wrap)V(khbox)        // 新增，宏展开后自动调用 _register_khbox()V(locks)

** 在  **` **RegisterExternalReferences**  ` ** 里注册外部引用：  **


    void RegisterExternalReferences(ExternalReferenceRegistry* registry) {  registry->Register(GetLinkedBinding);  registry->Register(GetInternalBinding);  khbox::RegisterExternalReferences(registry);  // 新增}

第三处是 Node.js 快照机制要求的——所有在 C++ 层注册的函数指针必须在这里声明，否则带快照编译时会崩溃。

###  3\.  ` src/node_contextify.cc  ` — 可选扩展点

这是  ` vm  ` 模块的核心实现，属性 Get/Set 的拦截可以在这里做。khBox 目前这部分由 addon 逻辑接管，这个文件  ** 不需要改
** 。但如果你想在 vm 模块层面做 wrapper，这里是也是一个实现全局hook的点。

###  4\.  ` lib/internal/bootstrap/node.js  ` — 挂载全局变量

这是 Node.js 启动时最早执行的 JS 引导文件。在这里把 khBox 的 C++ binding 挂到  ` globalThis  `
上，写到文件最后就行。让所有 JS 代码都能直接访问：


    const khboxBinding = internalBinding('khbox');
    Object.defineProperty(globalThis, 'khBox', {  get() { return khboxBinding; },  enumerable: false,   // 不出现在 Object.keys(globalThis) 里  configurable: false});

` enumerable: false  ` 让它不暴露在键枚举里，对外不可见。  ` internalBinding('khbox')  `
对应的就是上一步在  ` node_binding.cc  ` 里注册的模块名。

好了，这三个一改，就可以了。当然也得把khbox一堆代码放到目录里。


##  编译和验证

改完四个文件，把 khBox 源文件放到  ` src/khbox/  ` 目录，然后跑编译：


    .\vcbuild.bat

编译成功在  ` Release\node.exe  ` ，替换掉本地 Node 安装目录里的  ` node.exe  ` （先备份）。

验证是否成功：


    node -e "console.log(khBox)"

输出 khBox 的对象信息而不是报错，说明模块注册成功，拦截层已经在位。
