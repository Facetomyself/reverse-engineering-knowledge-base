## 算法背景

Salsa20 由 Daniel J. Bernstein(简称 djb)于 2005 年设计,入选了 eSTREAM 流密码竞赛。它是 ChaCha20 的前身,两者核心思想一样,只是 Quarter Round 的操作顺序不同。
和 RC4 对比:RC4 靠 256 字节的 S-box 洗牌来生成密钥流;Salsa20 靠 512 位的状态矩阵做 ARX(加法+旋转+异或)运算来生成密钥流。Salsa20 的安全性远高于 RC4。

流密码的本质
所有流密码本质都是 密钥扩展器:把短密钥扩展成任意长度的伪随机流,然后 XOR 明文。每个流密码都分两步:
阶段
作用
类比
1 密钥调度(Key Setup)
短密钥 → 内部状态
往搅拌机里放原料
2 密钥流生成(PRGA)
内部状态 → 伪随机字节流
持续输出混合物
四种流密码的重心各不相同:

```
RC4:               KSA 复杂(256轮洗牌),PRGA 简单(查表)
Salsa20/ChaCha20:  Key Setup 极简(填矩阵),核心在 20轮ARX    ← 本文
Rabbit:            Key Setup 中等(交叉+4次迭代),G函数平方运算
```

Salsa20 的 Key Setup 简单到只是"把原料摆进矩阵",真正的魔法全在 20 轮 ARX 搅拌里。

## 1. 状态矩阵初始化

Salsa20 的核心是一个 4×4 的 32 位字矩阵(共 512 位 = 64 字节):

```
[常量0] [密钥0] [密钥1] [密钥2]
[密钥3] [常量1] [nonce0][nonce1]
[ctr_lo][ctr_hi][常量2] [密钥4]
[密钥5] [密钥6] [密钥7] [常量3]
注意对角线:4 个常量 "expand 32-byte k" 分布在对角线位置 [0,5,10,15]。这个设计确保即使密
```

钥和 nonce 全为 0,矩阵也不会全零。

```
# 常量 "expand 32-byte k" 的 ASCII 编码
SIGMA = [0x61707865, 0x3320646e, 0x79622d32, 0x6b206574]
x[0], x[5], x[10], x[15] = SIGMA  # 对角线放常量for i in range(4):
x[1+i] = struct.unpack('<I', key[i*4:(i+1)*4])[0]      # 密钥前半
x[11+i] = struct.unpack('<I', key[16+i*4:16+(i+1)*4])[0] # 密钥后半
x[8] = counter & 0xFFFFFFFF       # 计数器低32位
x[9] = (counter >> 32) & 0xFFFFFFFF  # 计数器高32位
x[6] = struct.unpack('<I', nonce[0:4])[0]  # Nonce 前半
x[7] = struct.unpack('<I', nonce[4:8])[0]  # Nonce 后半
```

## 2. Quarter Round(四分之一轮)

Salsa20 的核心操作,只用三种运算——ARX(三种操作的英文首字母):

```
Add(模 2^32 加法): (a+b) & 0xFFFFFFFF
```

Rotate(循环左移)
XOR(异或): ^

```
def _quarter_round(self, x, a, b, c, d):
x[b] ^= self._rotl((x[a] + x[d]) & 0xFFFFFFFF, 7)
x[c] ^= self._rotl((x[b] + x[a]) & 0xFFFFFFFF, 9)
x[d] ^= self._rotl((x[c] + x[b]) & 0xFFFFFFFF, 13)
x[a] ^= self._rotl((x[d] + x[c]) & 0xFFFFFFFF, 18)
```

每行都做同样的事:两个值相加 → 左移 → 异或到目标为什么只用 ARX? 因为这三种操作纯整数运算,不需要查表(没有 S-box),在任何 CPU 上都极快,而且天然抵抗侧信道攻击(时间恒定)。

## 3. 20 轮搅拌(10 个双轮)

每个双轮 = 列轮 + 行轮:

```
for round_num in range(10):
# 列轮: 按列做 Quarter Round
self._quarter_round(x, 0, 4, 8, 12)    # 第0列
self._quarter_round(x, 5, 9, 13, 1)    # 第1列
self._quarter_round(x, 10, 14, 2, 6)   # 第2列
self._quarter_round(x, 15, 3, 7, 11)   # 第3列
# 行轮: 按行做 Quarter Round
self._quarter_round(x, 0, 1, 2, 3)     # 第0行
self._quarter_round(x, 5, 6, 7, 4)     # 第1行
self._quarter_round(x, 10, 11, 8, 9)   # 第2行
self._quarter_round(x, 15, 12, 13, 14) # 第3行
```

列轮 + 行轮 确保矩阵每个位置的值都能影响到其他所有位置。20 轮后扩散非常充分。

## 4. Feedforward

搅拌完之后,把 20 轮的输出加上初始状态:

```
for i in range(16):
x[i] = (x[i] + initial[i]) & 0xFFFFFFFF
```

为什么要加回去? 如果不加,攻击者知道输出后可以反推回初始状态(因为 Quarter Round 都是可逆的)。加上初始状态后,即使知道输出也无法反推,因为不知道加法的进位。

将这个 4×4 矩阵按小端序展开成 64 字节,就是密钥流。

# 七、常见变种与非标准实现

Salsa20 结构非常规整,魔改通常集中在初始矩阵的填法上。

## 7.1 常见配置差异(非标准配置)

1. Nonce 和 计数器长度
标准 Salsa20 使用 8字节 Nonce + 8字节 Counter。 但很多现代变种(如 XSalsa20)或修改版会使用:
12字节 Nonce + 4字节 Counter (类似 IETF ChaCha20)
24字节 Nonce (XSalsa20)
识别:看初始矩阵第 3、4 行的填法。如果 Counter 只有 1 个字(32位),那大概率是改了 Nonce 长度。
2. 密钥长度
支持 16 字节(128位)和 32 字节(256位)。16 字节版本会使用不同的常量字符串 "expand 16-byte k"。

## 7.2 算法核心修改(真正的魔改)

1. 初始矩阵常量 (Magic Constants)
最常见的魔改点。标准常量是 "expand 32-byte k" 的 ASCII 码。 魔改:替换这 16 个字节的常量字符串。

```
识别:搜索 0x61707865 (expa),如果找不到但看到类似的代码结构,可能就是改了字符串。
```

2. 轮数修改
标准是 20 轮。 常见变种:
Salsa20/8 (8轮):速度极快,用于老旧设备,安全性稍低。
Salsa20/12 (12轮):平衡之选(eSTREAM 推荐配置)。
