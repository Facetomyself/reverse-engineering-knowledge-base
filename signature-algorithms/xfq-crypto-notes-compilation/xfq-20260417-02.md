# 结论先放前面 🔝

```
输入 b"123456" 时,libmfw.so 这套签名逻辑不是标准 SHA-1,最终魔改点一共 4 类:
```

1. 初始 IV 改了

```
H0 = 0x67452301
H1 = 0xefcdab89
H2 = 0x98badcfe
H3 = 0x5e4a1f7c
H4 = 0x10325476
2. 消息扩展 W[16..79] 没改
仍然是 ROTL1(W[i-3] ^ W[i-8] ^ W[i-14] ^ W[i-16])
```

3. 80 轮分段逻辑改了

```
0..15 : Ch + 0x5A827999
16..19 : Par + 0x6ED9EBA1
20..39 : Maj + 0x8F1BBCDC
40..59 : Ch + 0x5A827999
60..79 : Par + 0xCA62C1D6
```

4. 最终 feed-forward 改了

```
标准 SHA-1:H2 += c, H3 += d
这里变成:H2 += d, H3 += c
```

最终输出和 trace 一致:

```
2f45b7dd81d48343c79ddbc14cddb756d7353190
```

# 7.真正值得记住的方法论 🔝

从最终输出 5 word 开始
把 message block 和 padding 锁死跑标准可读实现,逐轮打印每次只改一个因素用 first mismatch round 找分界点

```
用 rg.exe 搜真值 / 假值,回到 trace 验证
```

最后再拿早期内存布局当辅助证据闭环
这个顺序更稳,也更能应对混淆样本。
