```
def pkcs7_padding(self, data: bytes) -> bytes:
"""
PKCS#7 填充:
DES 块大小为 8 字节 (64位)。
如果数据长度不是 8 的倍数,需要进行填充。
填充规则: 缺少 n 个字节,就填充 n 个字节,每个字节的值都是 n。
例如: 数据长度为 5,缺 3 个字节满 8,则填充 3 个 0x03。
如果数据长度刚好是 8 的倍数,则填充 8 个 0x08 (增加一个完整块)。
"""
pad_len = 8 - (len(data) % 8)
return data + bytes([pad_len] * pad_len)
```

有时,有些案例用的不是这个填充,需要注意!

```
def feistel_function(self, right_half: str, subkey: str) -> str:
"""
Feistel 轮函数 F(R, K):
输入: 32位 数据 R, 48位 子密钥 K
输出: 32位 数据
流程: E扩展 -> 异或 -> S盒代换 -> P置换
"""
logger.debug(f"Feistel函数输入 R: {right_half}")
logger.debug(f"子密钥: {subkey}")
# 1. 扩展置换 (E-Expansion)
# 将 32位 数据 R 扩展为 48位,目的是与 48位 子密钥进行异或
# 扩展方法是重复某些位
expand_r0 = [right_half[pos] for pos in self.E]
expanded_str = "".join(expand_r0)
logger.debug(f"扩展后: {expanded_str}")
# 2. 密钥加 (Key Mixing)
# 将扩展后的 48位 数据与 48位 子密钥进行异或运算
xor_result = self.xor_binary_strings(expanded_str, subkey)
logger.debug(f"异或结果: {xor_result}")
# 3. S盒代换 (Substitution Box)
# 将 48位 数据压缩回 32位 (非线性变换,DES 安全性的核心)
# 将 48位 分为 8 组,每组 6 位,分别进入 8 个 S盒
sbox_result = self.s_box_substitution(xor_result)
logger.debug(f"S盒后: {sbox_result}")
# 4. P盒置换 (Permutation)
# 对 S盒输出的 32位 数据进行最后一次线性打乱
pbox_result = [sbox_result[pos-1] for pos in self.P]
pbox_str = "".join(pbox_result)
logger.debug(f"P盒后: {pbox_str}")
return pbox_str
```

# 四、CBC模式

## 4.1 为啥要有CBC模式

CBC(Cipher Block Chaining,密码块链接)模式主要是为了防止密文的模式泄露,从而抵御“密文重放”或“ECB弱点”攻击。
25

### 1. ECB模式的缺陷

ECB如何工作
将明文分成独立的块,然后用相同的密钥对每一块进行单独加密。

```
1
2
3
明文块1 → DES加密 → 密文块1
明文块2 → DES加密 → 密文块2
明文块3 → DES加密 → 密文块3
```

ECB的致命弱点
相同的明文块总是会生成相同的密文块 ⚠️
举例
如果明文多段重复,密文也会出现多段重复。攻击者可以:
●
发现重复模式
●
利用不同输入获取输出
●
可能爆破出密钥
结论
ECB模式不安全,绝对不应该用于加密有意义的数据。

### 2. CBC如何解决这个问题

CBC通过引入“链式”结构和“初始化向量(IV)”来确保即使明文块相同,加密后的密文块也完全不同。
核心机制
●
1 初始化向量(IV)
○
一个随机的、不重复的数据块
○
用于加密第一个明文块
●
2 异或(XOR)操作
○
加密前,当前明文块先与前一个密文块异或
○
第一个块与IV异或
●
3 链式依赖
26
○
每个密文块依赖当前明文块及所有之前的明文块
○
修改任何一个比特,会导致其后所有密文块完全改变

### 3. CBC加解密流程

加密流程

```
1
2
3
4
5
6
生成随机IV
第一块: 密文1 = DES_Encrypt(明文1 ⊕ IV, 密钥)
第二块: 密文2 = DES_Encrypt(明文2 ⊕ 密文1, 密钥)
第三块: 密文3 = DES_Encrypt(明文3 ⊕ 密文2, 密钥)
...
```

解密流程

```
1
2
3
4
第一块: 明文1 = DES_Decrypt(密文1, 密钥) ⊕ IV
第二块: 明文2 = DES_Decrypt(密文2, 密钥) ⊕ 密文1
第三块: 明文3 = DES_Decrypt(密文3, 密钥) ⊕ 密文2
...
```

### 4. CBC的安全考虑

虽然CBC解决了ECB的核心问题,但仍需注意:
1 填充Oracle攻击
●
如果解密时泄露“填充是否正确”的信息
●
攻击者可以逐字节解密密文(无需密钥)
2 不提供完整性保护
●
CBC只提供保密性,不提供完整性
●
攻击者可以篡改密文
●
建议结合HMAC或使用AEAD模式(如AES-GCM)
3 IV必须正确使用
●
IV必须随机且不可预测
27
●
每次加密使用不同的IV
●
IV重用会导致安全问题
