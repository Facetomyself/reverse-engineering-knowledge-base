## 算法背景

ChaCha20 是 Bernstein 在 2008 年对自己的 Salsa20 做的改进。核心算法框架完全一样——都是 4×4 状态矩阵+ 20 轮 ARX + Feedforward,改的是两个地方:
改进 1:Quarter Round 操作顺序

```
Salsa20:  b ^= rotl(a + d, 7)     → 先加后转再异或
ChaCha20: a += b; d ^= a; d = rotl(d, 16)  → 先加再异或后转
```

ChaCha20 的版本每一步都立即把结果反馈给下一步,扩散更快。
改进 2:对角轮替代行轮

```
Salsa20:  列轮 + 行轮
ChaCha20: 列轮 + 对角轮
```

对角轮的扩散路径更长——每个字和对角线上的字交互,比行内交互跨度更大。
结果:ChaCha20 用同样的 20 轮就能达到比 Salsa20 更好的扩散效果。这也是为什么 Google、
Cloudflare 等都选择 ChaCha20 而不是 Salsa20。
流密码的本质
所有流密码本质都是 密钥扩展器:把短密钥扩展成任意长度的伪随机流,然后 XOR 明文。每个流密码都分两步:
阶段
作用
类比
1 密钥调度(Key Setup)
短密钥 → 内部状态
往搅拌机里放原料
2 密钥流生成(PRGA)
内部状态 → 伪随机字节流
持续输出混合物
四种流密码的重心各不相同:

```
RC4:               KSA 复杂(256轮洗牌),PRGA 简单(查表)
Salsa20/ChaCha20:  Key Setup 极简(填矩阵),核心在 20轮ARX    ← 本文
Rabbit:            Key Setup 中等(交叉+4次迭代),G函数平方运算
```

ChaCha20 和 Salsa20 一样,Key Setup 就是填矩阵。差异全在 Quarter Round 和轮结构上——同样的
20 轮 ARX,ChaCha20 扩散更快。

## 1. 状态矩阵初始化

ChaCha20 和 Salsa20 的矩阵布局不同:

```
Salsa20 布局:                    ChaCha20 布局:
[常量0] [密钥0] [密钥1] [密钥2]  [常量0] [常量1] [常量2] [常量3]  ← 常量在一行
[密钥3] [常量1] [nonce0][nonce1]  [密钥0] [密钥1] [密钥2] [密钥3]
[ctr_lo][ctr_hi][常量2] [密钥4]  [密钥4] [密钥5] [密钥6] [密钥7]
[密钥5] [密钥6] [密钥7] [常量3]  [ctr_lo][ctr_hi][nonce0][nonce1]  ← counter+nonce
```

在一行
Salsa20 把常量散在对角线上,ChaCha20 把常量集中在第一行。两种布局各有道理,但 ChaCha20 的布局让实现更简洁。

```
# 常量(第一行)
state[0:4] = SIGMA  # "expand 32-byte k"
# 密钥(第二、三行)for i in range(8):
state[4+i] = struct.unpack('<I', key[i*4:(i+1)*4])[0]
# 计数器 + Nonce(第四行)
state[12] = counter & 0xFFFFFFFF
state[13] = (counter >> 32) & 0xFFFFFFFF
state[14] = struct.unpack('<I', nonce[0:4])[0]
state[15] = struct.unpack('<I', nonce[4:8])[0]
```

## 2. Quarter Round 详解

```
ChaCha20 的 QR 有 4 步,每步都是 加法 → 异或 → 循环左移:
def _quarter_round(self, state, a, b, c, d):
state[a] = (state[a] + state[b]) & 0xFFFFFFFF; state[d] ^= state[a]; state[d]
= self._rotl(state[d], 16)
state[c] = (state[c] + state[d]) & 0xFFFFFFFF; state[b] ^= state[c]; state[b]
= self._rotl(state[b], 12)
state[a] = (state[a] + state[b]) & 0xFFFFFFFF; state[d] ^= state[a]; state[d]
= self._rotl(state[d], 8)
state[c] = (state[c] + state[d]) & 0xFFFFFFFF; state[b] ^= state[c]; state[b]
= self._rotl(state[b], 7)
```

对比 Salsa20 的 QR(操作顺序完全不同):

```
# Salsa20: 先 (a+d) 再 rotl 再 ^= b
state[b] ^= self._rotl((state[a] + state[d]) & 0xFFFFFFFF, 7)
state[c] ^= self._rotl((state[b] + state[a]) & 0xFFFFFFFF, 9)
state[d] ^= self._rotl((state[c] + state[b]) & 0xFFFFFFFF, 13)
state[a] ^= self._rotl((state[d] + state[c]) & 0xFFFFFFFF, 18)
移位量也不同:ChaCha20 用 16, 12, 8, 7,Salsa20 用 7, 9, 13, 18。
```

## 3. 列轮 + 对角轮

每个双轮 = 列轮 + 对角轮(Salsa20 是列轮 + 行轮):

```
for round_num in range(10):
# 列轮: 和 Salsa20 一样
self._quarter_round(state, 0, 4, 8, 12)   # 第0列
self._quarter_round(state, 1, 5, 9, 13)   # 第1列
self._quarter_round(state, 2, 6, 10, 14)  # 第2列
self._quarter_round(state, 3, 7, 11, 15)  # 第3列
# 对角轮: Salsa20 的行轮变成了对角轮
self._quarter_round(state, 0, 5, 10, 15)  # 主对角线
self._quarter_round(state, 1, 6, 11, 12)  # 次对角线
self._quarter_round(state, 2, 7, 8, 13)
self._quarter_round(state, 3, 4, 9, 14)
```


# 八、常见变种与非标准实现

ChaCha20 是目前最主流的流密码,其变种主要体现在标准化差异上。

## 7.1 常见配置差异(非标准配置)

1. IETF vs Bernstein (Nonce 长度)
这是最大的坑。
Bernstein 原版:8 字节 Nonce + 8 字节 Counter。
IETF RFC 7539:12 字节 Nonce + 4 字节 Counter(最常见,用于 TLS/WireGuard)。
XChaCha20:24 字节 Nonce(用于随机 Nonce 场景)。
影响:初始矩阵的第 12~15 字填法不同。
2. 计数器起始值
标准通常从 0 开始。
有些实现(如 TLS)可能从 1 开始。

## 7.2 算法核心修改(真正的魔改)

1. 初始矩阵常量
同 Salsa20,标准是 "expand 32-byte k"。 魔改:修改这个字符串。
2. 轮数修改
ChaCha8 (8轮):极速,某些轻量级加密使用。
ChaCha12 (12轮)。
3. Quarter Round 参数

```
标准移位量是 16, 12, 8, 7。 魔改:修改这组移位量。
```
