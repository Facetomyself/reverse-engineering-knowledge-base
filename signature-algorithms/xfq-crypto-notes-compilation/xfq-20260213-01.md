## 1. 密钥扩展

Twofish 的密钥扩展需要生成三样东⻄:40 个子密钥 + 4 个密钥依赖的 S-box。
1.1 密钥分割
将密钥按 小端序 转成 32 位字,然后分为偶数组 Me 和奇数组 Mo:

```
# 将密钥分为 32 位字 (little-endian)
M = []
for i in range(0, key_len, 4):
M.append(int.from_bytes(key[i:i+4], 'little'))
# 分离 Me (偶数索引) 和 Mo (奇数索引)
Me = [M[2*i] for i in range(self.k)]
Mo = [M[2*i+1] for i in range(self.k)]
```

测试数据:

```
密钥 secretkeysecretk 的十六进制是 73 65 63 72 65 74 6b 65 79 73 65 63 72 65 74 6b。
```

第一步:每 4 字节转成一个 32 位字(小端序 = 字节顺序反转)

```
M[0]: 取 key[0:4]  = 73 65 63 72 → 小端序反转 → 72 63 65 73 → 0x72636573   ("secr"
→ 倒过来)
M[1]: 取 key[4:8]  = 65 74 6b 65 → 小端序反转 → 65 6b 74 65 → 0x656b7465   ("etke"

M[2]: 取 key[8:12] = 79 73 65 63 → 小端序反转 → 63 65 73 79 → 0x63657379   ("ysec"

M[3]: 取 key[12:16]= 72 65 74 6b → 小端序反转 → 6b 74 65 72 → 0x6b746572   ("retk"

小端序就是 低位字节在前、高位字节在后。int.from_bytes(b'\x73\x65\x63\x72', 'little') 会
把 0x73 当最低字节,所以结果是 0x72636573。
```

第二步:按奇偶索引分组

```
Me (偶数索引): M[0] = 0x72636573, M[2] = 0x63657379
Mo (奇数索引): M[1] = 0x656b7465, M[3] = 0x6b746572
```

为什么分两组?Me 用来生成子密钥的一半(A 值),Mo 生成另一半(B 值),最后合并。
1.2 RS 矩阵生成 S-box 密钥
RS 矩阵是什么? 一个 4×8 的矩阵,作用是把 8 字节密钥块"压缩"成 4 字节的 S-box 密钥。
对比 Blowfish:Blowfish 靠 521 次加密来生成 S-box 内容,Twofish 用 RS 矩阵做一次矩阵乘法就算出来了。
这里的乘法不是普通整数乘法,而是 GF(2^8) 有限域乘法。
GF(2^8) 是什么? 不用怕,其实就是一种"特殊的字节运算规则":
加法 = 异或(XOR),不是普通加法
乘法 = 多项式乘法再取模,类似整数乘法后取余数

```
每个字节(0~255)都可以看成一个多项式,比如 0x53 = 01010011 就是 x^6 + x^4 + x + 1
```

乘完之后如果超过 8 位,就对一个固定的"模多项式"取余(就像整数除以某个数取余数一样)
Twofish 里有两个不同的模多项式,RS 和 MDS 各用一个:

```
RS 矩阵用:x^8 + x^6 + x^3 + x^2 + 1(约化常数 0x4D)
MDS 矩阵用:x^8 + x^6 + x^5 + x^3 + 1(约化常数 0x69)
def _rs_multiply(self, vec: List[int]) -> int:
"""RS 矩阵乘法,生成 S-box 密钥"""
result = [0, 0, 0, 0]for i in range(4):for j in range(8):
result[i] ^= self._gf_mult_rs(self.RS[i][j], vec[j])
return self._bytes_to_word(result)
8 字节密钥块  →  RS 矩阵乘法 (GF(2^8))  →  4 字节 S-box 密钥
```

测试数据:

```
块0: [73 65 63 72 65 6b 74 65] → RS → 0x6a0ebf58
块1: [79 63 65 73 72 74 65 6b] → RS → 0x8e8f3280
S-box 密钥 (反转后): ['0x80328f8e', '0x58bf0e6a']
```

为什么要反转?Twofish 论文规定 S-box 密钥的顺序是 S[k-1]...S[0],最后生成的排在前面。
1.3 生成 40 个子密钥
使用 h 函数 分别处理 Me 和 Mo,然后合并出 40 个 32 位子密钥。
h 函数是什么? 可以理解为 Twofish 的核心"搅拌函数"——输入一个 32 位值和密钥,经过多层 q 置换 + 密钥字节异或 + MDS 矩阵乘法,输出一个 32 位值。
q0 和 q1 就是两个 256 字节的固定查找表——输入一个字节查出另一个字节(类似 AES 的 S-box),交替使用避免单一替换表被攻击。
代码看起来很吓人,其实就是嵌套查表 + 异或密钥:

```
def _h_func(self, X: int, L: List[int]) -> int:
y = self._word_to_bytes(X)
# 128-bit key: 每个字节经过两层 "q置换 + 密钥异或"
y[0] = self.Q0[self.Q0[y[0]] ^ ((L[1] >> 0) & 0xFF)] ^ ((L[0] >> 0) & 0xFF)
y[1] = self.Q0[self.Q1[y[1]] ^ ((L[1] >> 8) & 0xFF)] ^ ((L[0] >> 8) & 0xFF)
y[2] = self.Q1[self.Q0[y[2]] ^ ((L[1] >> 16) & 0xFF)] ^ ((L[0] >> 16) & 0xFF)
y[3] = self.Q1[self.Q1[y[3]] ^ ((L[1] >> 24) & 0xFF)] ^ ((L[0] >> 24) & 0xFF)
return self._mds_multiply(y)
```

拆开来看其实就两步(以 y[0] 为例):

```
原始代码: y[0] = Q0[ Q0[y[0]] ^ key_byte_1 ] ^ key_byte_0
拆解:
第1层: temp = Q0[y[0]]           # 先查一次 q0 表
temp = temp ^ key_byte_1   # 异或 L[1] 的第0个字节
第2层: temp = Q0[temp]            # 再查一次 q0 表
y[0] = temp ^ key_byte_0   # 异或 L[0] 的第0个字节
```

每个字节走两层,每层都是"查表 → 异或密钥字节"。4 个字节分别走不同的 q0/q1 组合,这样扩散更充分。
流程图:

```
输入 X (32位) → 拆成 4 字节 [y0, y1, y2, y3]
↓
y0: Q0 → ⊕L[1]字节0 → Q0 → ⊕L[0]字节0
y1: Q1 → ⊕L[1]字节1 → Q0 → ⊕L[0]字节1
y2: Q0 → ⊕L[1]字节2 → Q1 → ⊕L[0]字节2
y3: Q1 → ⊕L[1]字节3 → Q1 → ⊕L[0]字节3
↓
[y0', y1', y2', y3'] → MDS 矩阵乘法 → 32 位输出
```

有了 h 函数之后,子密钥生成就是:

```
rho = 0x01010101for i in range(20):
A = self._h_func(2*i * rho, Me)        # 用 Me 算 A
B = self._rotl(self._h_func((2*i+1) * rho, Mo), 8)  # 用 Mo 算 B,再左移8位
self.K.append((A + B) & 0xFFFFFFFF)                  # K[2i] = A + B
self.K.append(self._rotl((A + 2*B) & 0xFFFFFFFF, 9)) # K[2i+1] = ROL(A + 2B,
9)
```

这里用到了 PHT(伪 Hadamard 变换) 的变体来合并 A 和 B:

```
K[2i] = A + B
K[2i+1] = ROL(A + 2B, 9)
```

PHT 是什么? 就是把两个值加法混合:a' = a + b, b' = a + 2b。效果是改变 A 或 B 的任何一个,两个子密钥都会变。多了一个循环左移 9 位,让子密钥之间差异更大。
测试数据:

```
子密钥 K[0:4]: ['0x9a2529a1', '0x85589d2f', '0xcd3b2821', '0xb309eb62']
```

1.4 生成密钥依赖 S-box
Twofish 有 4 个 S-box,每个 256 字节,内容取决于密钥(不像 AES 的 S-box 是固定的)。
生成方式:对每个输入字节(0~255),经过 q 置换表和 S-box 密钥的多轮异或:

```
def _generate_sboxes(self, S_keys: List[int]):
"""生成密钥依赖的 S-box"""
self.S = [[], [], [], []]for i in range(256):for j in range(4):
x = i
if self.k == 4:  # 256-bit key
x = self.Q1[x] ^ ((S_keys[3] >> (j*8)) & 0xFF)
if self.k >= 3:  # 192-bit key
x = self.Q1[x] ^ ((S_keys[2] >> (j*8)) & 0xFF)
# 128-bit key (always)
x = self.Q0[x] ^ ((S_keys[1] >> (j*8)) & 0xFF)
x = self.Q1[x] ^ ((S_keys[0] >> (j*8)) & 0xFF)self.S[j].append(x)
```

对比 Blowfish:Blowfish 的 4 个 S-box 靠 521 次全零加密迭代生成,非常慢;Twofish 靠 q 置换 + S-box 密钥异或直接计算,快得多。
到这里密钥扩展就完成了,我们得到了:

```
40 个 32 位子密钥 K[0]~K[39]
```

4 个密钥依赖的 S-box(各 256 字节)

3.2 单块加密
这里要引入一个概念——输入/输出白化(Whitening)。
白化是什么? 就是在正式加密轮次的 前后 各异或一组子密钥。名字来自信号处理,让数据看起来像"白噪声"一样随机。具体做法很简单:
加密开始前:明文 ⊕ K[0..3](输入白化)
加密结束后:结果 ⊕ K[4..7](输出白化)
白化的好处:攻击者无法直接看到第一轮和最后一轮的真实输入输出,增加了分析难度。Blowfish 没有白化,
Twofish 加了这步。

```
def _encrypt_block(self, block: bytes) -> bytes:
"""加密单个 128 位块"""
# 分为 4 个 32 位字 (little-endian)
R = [int.from_bytes(block[i:i+4], 'little') for i in range(0, 16, 4)]
# 1 输入白化:异或前4个子密钥for i in range(4):
R[i] ^= self.K[i]
# 2 16 轮 Feistelfor r in range(16):
T0, T1 = self._f_func(R[0], R[1], r)
R[2] = self._rotr((R[2] ^ T0), 1)
R[3] = self._rotl(R[3], 1) ^ T1
R[0], R[1], R[2], R[3] = R[2], R[3], R[0], R[1]
# 撤销最后一次交换
R[0], R[1], R[2], R[3] = R[2], R[3], R[0], R[1]
# 3 输出白化:异或 K[4..7]for i in range(4):
R[i] ^= self.K[4 + i]
return b"".join(w.to_bytes(4, 'little') for w in R)
```

## 4. 16 轮 Feistel 网络

4.1 每轮操作
跟 Blowfish 不同,Blowfish 是经典的 2 路 Feistel(L/R 两路),Twofish 是 4 路 Feistel(R[0]~R[3])。
每一轮做以下操作:

```
R[0], R[1] → F函数 → (T0, T1)
R[2] = ROR(R[2] ⊕ T0, 1)    ← 先异或,再右移1位
R[3] = ROL(R[3], 1) ⊕ T1    ← 先左移1位,再异或
交换: R[0],R[1] ↔ R[2],R[3]
```

4.2 F 函数
F 函数是每一轮的核心,由 g 函数 + PHT + 子密钥混合 三步组成:

```
def _f_func(self, R0: int, R1: int, r: int) -> Tuple[int, int]:
"""F 函数:g + PHT + 子密钥"""
T0 = self._g_func(R0)
T1 = self._g_func(self._rotl(R1, 8))  # R1 先左移8位
# PHT + 子密钥
F0 = (T0 + T1 + self.K[8 + 2*r]) & 0xFFFFFFFF
F1 = (T0 + 2*T1 + self.K[9 + 2*r]) & 0xFFFFFFFF
return F0, F1
```

F 函数流程:

```
R0 ─────────→ g(R0) ──→ T0 ─┐
├→ PHT: F0 = T0 + T1 + K[8+2r]
R1 → ROL(8) → g(R1') ─→ T1 ─┤       F1 = T0 + 2·T1 + K[9+2r]
└→ 输出 (F0, F1)
```

注意 R1 先循环左移 8 位再进 g 函数,让 R0 和 R1 走的路径不完全对称。
4.3 g 函数
g 函数 = S-box 查表 + MDS 矩阵乘法,是 Feistel 每一轮做非线性变换的关键:

```
def _g_func(self, X: int) -> int:
"""g 函数:S-box 查表 + MDS"""
b = self._word_to_bytes(X)
# S-box 查表(密钥依赖的 S-box)
y = [self.S[i][b[i]] for i in range(4)]
# MDS 矩阵乘法
return self._mds_multiply(y)
举个例子,假设输入 X = 0xf54040d9(输入白化后 R[0] 的值可能是这个):
1 拆字节 (小端序): [d9, 40, 40, f5]
2 S-box 查表:
S[0][0xd9] → 某个值 a
S[1][0x40] → 某个值 b
S[2][0x40] → 某个值 c
S[3][0xf5] → 某个值 d
3 [a, b, c, d] → MDS 矩阵乘法 → 32 位输出
```

关键点:S-box 是密钥依赖的(在密钥扩展阶段生成),不同密钥下查同一个字节会得到不同结果。这是 Twofish 安全性的重要来源。
4.4 MDS 矩阵乘法
MDS(Maximum Distance Separable)矩阵 是一个 4×4 矩阵,在 GF(2^8) 上运算。
MDS 的核心特点:改变输入的任何 1 个字节,输出的 4 个字节全都会变(完全扩散)。这跟 AES 的MixColumns 步骤类似。

```
MDS = [
[0x01, 0xEF, 0x5B, 0x5B],
[0x5B, 0xEF, 0xEF, 0x01],
[0xEF, 0x5B, 0x01, 0xEF],
[0xEF, 0x01, 0xEF, 0x5B],
]
```

矩阵乘法:每个输出字节 = 矩阵的一行和输入的点积(GF(2^8) 的加法就是 XOR):

```
def _mds_multiply(self, y: List[int]) -> int:
result = [0, 0, 0, 0]for i in range(4):for j in range(4):
result[i] ^= self._gf_mult(self.MDS[i][j], y[j])  # "乘"再"加"(XOR)
return self._bytes_to_word(result)
其中 _gf_mult 是 GF(2^8) 乘法的核心,逐行解释:
def _gf_mult(self, a: int, b: int) -> int:
"""GF(2^8) 乘法"""
result = 0
for _ in range(8):        # 循环8次(b 有 8 个 bit)
if b & 1:             # 如果 b 的最低位是 1
result ^= a       #   就把 a 累加(XOR)到结果里
hi_bit = a & 0x80     # 记住 a 的最高位
a = (a << 1) & 0xFF   # a 左移一位(相当于乘以 x)
if hi_bit:            # 如果左移前最高位是 1,说明溢出了
a ^= 0x69         #   就异或模多项式的低 8 位来"取余"
b >>= 1               # b 右移一位,准备处理下一个 bit
return result
直觉理解:这就是"手算乘法"。小学我们做十进制乘法是逐位乘再加;这里是逐 bit 乘(b & 1 决定加不
```

加),用 XOR 代替加法,溢出时用模多项式"取余"。

```
对比 Blowfish:Blowfish 的 F 函数用 ((S[0][a] + S[1][b]) XOR S[2][c]) + S[3][d],用加法和
```

异或混合。Twofish 用 MDS 矩阵做 GF(2^8) 乘法,数学上扩散性更强。

## 5. 完整流程

```
输入: 明文 (16字节) + 密钥 (16/24/32字节)
【1. 密钥扩展】
密钥 → 分割 Me/Mo → RS矩阵生成S-box密钥 → h函数生成40个子密钥 → 生成4个S-box
↓
【2. 数据填充】
PKCS#7填充 → 16字节的倍数
↓
【3. 逐块加密】(每块16字节)
128位明文 → 拆分4个32位字 (little-endian)
↓
1 输入白化: R[i] ⊕ K[i]
↓
2【16轮Feistel迭代】
F函数: g(R0) + g(ROL(R1,8)) → PHT → 加子密钥
R[2] = ROR(R[2] ⊕ F0, 1)
R[3] = ROL(R[3], 1) ⊕ F1
交换: R[0],R[1] ↔ R[2],R[3]
↓
3 输出白化: R[i] ⊕ K[4+i]
↓
输出: 密文
```

## 8. 为什么 Twofish 没有成为 AES?

虽然 Twofish 安全性很高,但 Rijndael(现在的 AES)最终胜出,原因:
1. 性能: Rijndael 在各种平台上性能更均衡
2. 简洁性: Rijndael 结构更简单(SPN 结构 vs Feistel),更易于分析和验证安全性
3. 硬件实现: Rijndael 更适合硬件加速(后来 Intel 做了 AES-NI 指令集)
4. Twofish 太复杂: 密钥依赖 S-box + RS/MDS 双矩阵 + PHT,实现复杂度高
Twofish 是一个优秀的算法,很多大厂的算法会使用twofish算法作为其中一套算法 或者 参考twofish的优点来设计自定义算法。
